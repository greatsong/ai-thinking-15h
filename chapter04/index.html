    4회차: 해결 절차 설계하기¶

    소속 계층: Layer 1 — 구조적 사고력 ("어떻게 생각할 것인가") 회차: 4/10 (Layer 1의 마지막 회차) 시간: 90분 핵심 질문: "분해하고, 패턴 찾고, 핵심 추출했는데... 이걸 어떤 순서로 실행하지?" Bloom's Taxonomy 수준: 분석(Analyze) — 구성 요소 간 관계를 파악하고 통합적 구조를 설계한다

    학습 목표¶

    이 회차를 마치면 학습자는 다음을 할 수 있습니다.

    1. 알고리즘 설계(Algorithm Design)의 개념을 이해하고 절차적 사고를 적용할 수 있다
    2. CT 4요소(분해, 패턴 인식, 추상화, 알고리즘 설계)를 통합하여 하나의 완전한 설계서를 작성할 수 있다
    3. 다른 사람의 설계서를 검증 체크리스트로 평가하고 건설적 피드백을 제공할 수 있다

    이 회차의 위치와 의미¶

    4회차는 Layer 1의 마무리이자 종합입니다. 지난 3회차에 걸쳐 하나씩 익힌 CT 4요소를 이번에 처음으로 하나의 완결된 설계서로 통합합니다.

    1회차: CT 전체 조감 + 분해 첫 경험
2회차: 분해(Decomposition) 심화 + MECE
3회차: 패턴 인식(Pattern Recognition) + 추상화(Abstraction)
4회차: 알고리즘 설계(Algorithm Design) + CT 4요소 종합  ← 지금 여기
─────────────────────────────────────────────────────
5회차부터: Layer 2 — 이 사고력을 AI와 함께 사용합니다

    이 회차가 끝나면 학생들은 "문제를 구조적으로 사고하는 프레임워크"를 갖추게 됩니다. 다음 회차부터는 AI가 등장하지만, AI에게 좋은 지시를 내리려면 이 프레임워크가 반드시 필요합니다. 그래서 4회차는 Layer 1의 종착점이자 Layer 2로 가는 다리 역할을 합니다.

    이 회차에서 AI 도구는 사용하지 않습니다. 마지막 AI-free 회차입니다.

    전체 흐름 (90분)¶

    단계 시간 목적
    도입 10분 1~3회차 빠른 복습 + "절차"의 필요성 체감
    탐색 15분 일상 속 절차를 설계해보는 개인/모둠 활동
    핵심 개념 15분 알고리즘 설계 + 순서도 + 조건 분기 + CT 종합
    실습 30분 CT 종합 설계서 작성 (Layer 1 최종 산출물)
    공유와 검증 15분 모둠 간 설계서 교환 + 종합 검증 체크리스트
    정리 5분 Layer 1 회고 + Layer 2 예고

    도입 (10분) — "재료는 준비됐는데, 순서가 없다"¶

    1~3회차 빠른 복습¶

    "지난 세 번의 수업에서 우리는 세 가지 강력한 도구를 익혔습니다."

    칠판이나 슬라이드에 다음을 제시합니다.

    [1회차] 분해 — 큰 문제를 작은 문제로 쪼개기
[2회차] 분해 심화 — MECE로 빠짐없이, 겹침없이
[3회차] 패턴 인식 + 추상화 — 공통 구조 발견 + 핵심만 남기기

    "이 세 가지를 모두 잘한다고 가정해봅시다. 문제를 쪼갰고, 패턴도 찾았고, 핵심도 뽑아냈습니다. 그런데... 뭔가 빠진 것 같지 않나요?"

    잠시 멈추고 학생들의 반응을 기다립니다.

    "맞습니다. 순서가 없습니다. 이걸 어떤 순서로 실행해야 할까요?"

    요리 레시피 비유¶

    "요리를 생각해봅시다. 볶음밥을 만든다고 해볼까요?"

    • 재료 준비 (분해): 밥, 달걀, 파, 간장, 기름
    • 조리 패턴 (패턴 인식): 대부분의 볶음 요리는 '기름 두르기 → 센 불에 볶기 → 양념 넣기' 패턴을 따른다
    • 핵심 원리 (추상화): "볶음의 핵심은 높은 온도에서 빠르게 수분을 날리는 것"

    "재료도 있고, 패턴도 알고, 원리도 이해했습니다. 그런데 여기서 달걀을 먼저 볶아야 할까요, 밥을 먼저 넣어야 할까요? 간장은 언제 넣어야 할까요?"

    "이 '순서'를 정하는 것, 그것이 바로 오늘 배울 알고리즘 설계입니다."

    재료(분해) + 조리법(패턴) + 핵심 원리(추상화) + 순서(알고리즘)
= 완성된 레시피

    "이 네 가지가 모여야 비로소 '누구나 따라 할 수 있는 레시피'가 됩니다. 오늘 우리는 이 마지막 퍼즐 조각을 채우고, 네 가지를 합쳐서 하나의 완전한 설계서를 만들어 볼 겁니다."

    진행자 팁: 복습은 빠르게 넘깁니다. 핵심은 "세 가지를 이미 알고 있는데, 하나가 더 필요하다"는 갈증을 만드는 것입니다. 학생들이 "순서!"라고 먼저 대답하면 "바로 그겁니다!"로 에너지를 높여주세요. 대답이 안 나와도 괜찮습니다. 요리 비유에서 자연스럽게 유도됩니다.

    탐색 (15분) — "먼저 절차를 설계해보자"¶

    활동 설명¶

    "지금부터 여러분이 직접 '절차'를 설계해볼 겁니다. 어렵게 생각하지 마세요. 우리는 이미 매일 절차를 따르며 살고 있습니다."

    활동 1: 개인 탐색 (5분)¶

    다음 두 가지 문제 중 하나를 선택하여 해결 절차를 단계별로 적어봅니다.

    문제 A: 학교 가는 최적 경로

    "집에서 학교까지 가는 가장 효율적인 방법을 설계하세요. 단, 다음 조건을 고려해야 합니다." - 날씨 (비가 오는 날 vs 맑은 날) - 시간 (여유 있는 날 vs 늦잠 잔 날) - 준비물 (체육복이 있는 날 vs 없는 날)

    문제 B: 시험 전날 공부 순서

    "내일 수학, 영어, 과학 시험이 있습니다. 오늘 저녁 4시간 동안 공부해야 합니다. 어떤 순서로, 각각 얼마나 공부할 것인지 절차를 설계하세요." - 수학: 이해는 됐지만 연습이 부족 - 영어: 단어 암기가 필요 - 과학: 개념 자체가 헷갈림

    각자 노트나 메모장에 번호를 붙여서 단계별로 적습니다.

    예시 형식:
1단계: ____________
2단계: ____________
3단계: ____________
  (만약 ____이면) → ____________
  (그렇지 않으면) → ____________
4단계: ____________
...

    활동 2: 모둠 공유 (10분)¶

    4인 1조로 모여 각자의 절차를 공유합니다. 진행자는 다음 질문으로 토론을 유도합니다.

    비교 질문: - "같은 문제를 골랐는데 절차가 다른 모둠원이 있나요? 왜 다를까요?" - "누군가의 절차에서 '만약 ~이면' 같은 조건이 들어간 부분이 있나요?" - "이 절차를 모르는 사람에게 주면, 그대로 따라 할 수 있을까요?"

    핵심 발견 유도: - "절차를 정할 때 가장 어려웠던 부분은 무엇인가요?" - "순서를 바꾸면 결과가 달라지는 경우가 있었나요?"

    진행자 팁: 학생들이 절차를 적을 때 "1. 공부한다 2. 잔다"처럼 너무 단순하게 적는 경우가 있습니다. 그럴 때는 "1단계 '공부한다'를 좀 더 구체적으로 쪼갤 수 있을까요? 어떤 과목을, 어떤 방법으로, 얼마나?"라고 질문하세요. 이것 자체가 분해(Decomposition)의 복습이 됩니다.

    진행자 팁: "만약 ~이면"이라는 표현이 자연스럽게 나오는 모둠이 있으면 크게 칭찬해주세요. 이것이 곧 다음 단계에서 배울 '조건 분기'입니다. "방금 여러분이 말한 '만약 비가 오면 버스, 안 오면 자전거' — 이것에 이름이 있습니다"로 핵심 개념 단계를 연결하면 됩니다.

    핵심 개념 (15분) — "절차에도 문법이 있다"¶

    알고리즘 설계란?¶

    "방금 여러분이 한 것, 그것이 알고리즘 설계(Algorithm Design)입니다."

    "알고리즘이라고 하면 프로그래밍이나 수학이 떠오를 수 있지만, 원래 의미는 훨씬 단순합니다. 문제를 해결하는 단계별 절차를 만드는 것입니다. 요리 레시피, 조립 설명서, 대피 매뉴얼 — 이 모든 것이 알고리즘입니다."

    알고리즘의 세 가지 조건을 제시합니다.

    조건 의미 예시
    명확성 각 단계가 모호하지 않아야 한다 "적당히 볶는다" (X) → "중불에서 3분 볶는다" (O)
    순서 단계의 순서가 정해져 있어야 한다 간장을 언제 넣느냐에 따라 맛이 달라진다
    종료 언젠가는 끝나야 한다 "완벽해질 때까지 반복" (X) → "3회 반복 후 마무리" (O)

    "좋은 알고리즘은 다른 사람이 이 절차만 보고 따라 해도 같은 결과를 얻을 수 있는 것입니다."

    순서도 그리기 기초¶

    "절차를 글로만 적으면 복잡해지기 쉽습니다. 그래서 순서도(Flowchart)라는 도구를 사용합니다."

    기본 기호를 소개합니다.

    ┌─────────────┐
│   시작/끝    │    ← 둥근 모서리: 시작과 끝
└─────────────┘

┌─────────────┐
│   처리 단계   │    ← 직사각형: 실행하는 행동
└─────────────┘

      ◇
     / \

    조건 분기(if-then)의 등장¶

    "순서도에서 가장 강력한 것은 마름모, 즉 조건 분기입니다."

    학교 가는 길 예시로 설명합니다.

        [시작: 등교 준비 완료]
            │
            ↓
      ◇ 비가 오는가? ◇
      │              │
    [예]            [아니오]
      │              │
      ↓              ↓
  [버스 타기]    ◇ 시간 여유? ◇
      │          │           │
      │        [예]        [아니오]
      │          │           │
      │          ↓           ↓
      │     [자전거]    [지하철]
      │          │           │
      └────┬─────┘───────────┘
           │
           ↓
      [학교 도착]

    "비가 오면 무조건 버스. 비가 안 오면 시간 여유에 따라 자전거 또는 지하철. 이것이 조건 분기입니다. 프로그래밍에서는 if-then-else라고 부르지만, 우리가 일상에서 매순간 하는 판단이 바로 이것입니다."

    한 걸음 더: 반복(Loop)¶

    "절차에는 '조건 분기' 말고도 반복이 있습니다."

        [시험 공부 시작]
          │
          ↓
    [문제 1개 풀기]
          │
          ↓
    ◇ 정답인가? ◇
    │           │
  [예]        [아니오]
    │           │
    │     [오답 노트 정리]
    │           │
    └─────┬─────┘
          │
          ↓
    ◇ 30분 지났는가? ◇
    │                │
  [예]             [아니오]
    │                │
    ↓            [처음으로 ↑]
  [다음 과목으로]

    "문제를 풀고, 틀리면 오답 노트를 정리하고, 30분이 안 됐으면 다시 문제를 풀고... 이 '돌아가기'가 반복입니다. 반복에는 반드시 종료 조건(여기서는 '30분')이 있어야 합니다. 그렇지 않으면 영원히 끝나지 않습니다."

    CT 4요소 종합 정리¶

    "이제 우리는 Computational Thinking의 4요소를 모두 배웠습니다."

    ┌────────────────────────────────────────────────────────────┐
│              Computational Thinking 4요소                    │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  [1] 분해 (Decomposition)                                   │
│      "큰 문제를 작은 문제로 쪼갠다"                           │
│      → 2회차에서 MECE 원칙까지 배웠습니다                     │
│                                                            │
│  [2] 패턴 인식 (Pattern Recognition)                        │
│      "서로 다른 문제에서 공통 구조를 찾는다"                   │
│      → 3회차에서 여러 문제의 공통 패턴을 발견했습니다          │
│                                                            │
│  [3] 추상화 (Abstraction)                                   │
│      "핵심만 남기고 불필요한 세부사항을 걸러낸다"              │
│      → 3회차에서 핵심 추출 연습을 했습니다                    │
│                                                            │
│  [4] 알고리즘 설계 (Algorithm Design)           ← 오늘!      │
│      "해결 절차를 단계별로 구성한다"                          │
│      → 순서, 조건 분기, 반복을 포함하는 절차 설계             │
│                                                            │
│  ═══════════════════════════════════════════                │
│  이 네 가지가 합쳐지면 → "완전한 설계서"가 됩니다             │
│                                                            │
└────────────────────────────────────────────────────────────┘

    각 요소가 어떻게 연결되는지 비유로 정리합니다.

    CT 요소 건축 비유 요리 비유 시험 준비 비유
    분해 건물을 층별/구역별로 나누기 재료를 종류별로 분류하기 과목별/단원별로 나누기
    패턴 인식 반복되는 층 구조 발견 볶음 요리의 공통 패턴 암기 과목 vs 이해 과목 패턴
    추상화 핵심 구조(골조)만 남기기 "높은 온도 + 빠른 조리" 원리 "개념 이해가 안 된 과목 먼저" 원칙
    알고리즘 설계 공사 순서와 일정표 조리 순서(레시피) 공부 순서와 시간 배분

    "1~3회차에서 우리는 재료를 준비하고 패턴을 찾고 핵심을 뽑아냈습니다. 오늘 '순서'를 더하면, 드디어 누구에게 주어도 실행할 수 있는 완전한 설계서가 됩니다."

    진행자 팁: 순서도 기호를 칠판에 그리면서 설명하면 효과적입니다. 학생들이 직접 칠판에 나와서 그려보게 하는 것도 좋습니다. "프로그래밍을 모르는 사람도 순서도는 읽을 수 있다"는 점을 강조하세요. 이것은 코딩이 아니라 사고를 시각화하는 도구입니다.

    진행자 팁: 학생들이 "이거 코딩 배우는 거 아니에요?"라고 물을 수 있습니다. "아닙니다. 코딩은 이 절차를 컴퓨터 언어로 옮기는 것이고, 지금 우리가 하는 것은 절차를 '설계'하는 것입니다. 설계가 좋으면 코딩은 AI가 대신 해줄 수 있지만, 설계는 여러분이 해야 합니다."라고 답하세요.

    실습 (30분) — "CT 종합 설계서 작성"¶

    과제 설명¶

    "오늘의 실습은 Layer 1의 최종 산출물입니다. 지금까지 배운 CT 4요소를 모두 적용하여, 여러분이 직접 선택한 문제에 대한 완전한 설계서를 작성합니다."

    "중요한 것은 결과의 '정답'이 아니라 네 가지 요소가 빠짐없이 적용되었는지, 그리고 이 설계서를 다른 사람이 보고 실행할 수 있는지입니다."

    동아리/행사 "학교 축제 부스 운영을 기획하는 방법"
    동아리/행사 "동아리 신입 부원 모집을 효과적으로 진행하는 방법"
    일상생활 "3박 4일 수학여행 짐 싸기를 빠짐없이 하는 방법"
    일상생활 "용돈을 한 달 동안 계획적으로 관리하는 방법"

    실습 진행 방법¶

    시간 활동 진행자 행동
    0~5분 문제 선택 + Part A 작성 순회하며 문제 선택을 도움
    5~15분 Part B~D 작성 "2~3회차에서 배운 것을 적용하세요"
    15~25분 Part E 작성 (핵심!) "조건 분기 하나는 꼭 포함하세요"
    25~30분 Part F 자기 검증 "체크 못한 항목은 수정 기회입니다"

    진행자 팁: Part A~D는 이미 2~3회차에서 연습한 내용이므로 비교적 빠르게 진행됩니다. 시간의 절반 이상을 Part E(알고리즘 설계)에 쓰도록 안내하세요.

    진행자 팁: 학생이 "조건 분기가 없어요"라고 하면, "정말 이 문제를 해결하는 데 아무런 판단이 필요 없나요? 어떤 상황이 달라지면 행동도 달라지는 경우가 없나요?"라고 질문하세요. 거의 모든 실생활 문제에는 조건 분기가 있습니다.

    진행자 팁: 순서도 그리기(E-4)에서 막히는 학생이 있을 수 있습니다. "먼저 E-1의 절차를 네모 상자로 그리고, 조건 분기 부분만 마름모로 바꿔보세요"라고 단계적으로 안내하면 됩니다. 순서도가 완벽할 필요는 없습니다. 핵심은 '절차를 시각화하려는 시도' 자체입니다.

    작성 예시 (학생 참고용)¶

    필요한 경우 다음 예시를 슬라이드로 보여줄 수 있습니다. 단, 실습 시작 전에 보여주면 학생들이 이것을 그대로 따라 하므로, 막히는 학생에게만 개별적으로 보여주는 것이 좋습니다.

    문제: "학급 발표 자료를 체계적으로 준비하는 방법"

    Part B (분해): 주제 선정 / 자료 조사 / 구조 설계 / 자료 제작 / 발표 연습

    Part C (패턴): "이것은 독서감상문 쓰기와 비슷하다. 둘 다 '주제 → 자료 수집 → 구조화 → 표현' 패턴을 따른다."

    Part D (추상화): 핵심은 "전달하고 싶은 메시지를 명확히 하고, 그것을 뒷받침하는 근거를 구조화하는 것". 폰트 종류나 애니메이션 효과는 비핵심.

    Part E (알고리즘): 1. 발표 주제 정하기 2. 핵심 메시지 한 문장으로 정리 3. 뒷받침 근거 3가지 조사 - 만약 근거가 3가지 안 되면 → 주제 범위 넓히기 - 3가지 이상이면 → 가장 강력한 3가지 선택 4. 슬라이드 구조 잡기 (서론-본론1-본론2-본론3-결론) 5. 슬라이드 제작 6. 발표 연습 (타이머 사용) - 만약 시간 초과면 → 내용 축소 후 6번 반복 - 시간 적정이면 → 7번으로 7. 최종 점검

    공유와 검증 (15분) — "이 설계대로 실행하면 해결될까?"¶

    검증 진행 방법¶

    시간 활동
    0~5분 다른 모둠의 설계서를 읽고 체크리스트 작성
    5~8분 체크리스트를 원래 모둠에 돌려주고 간단히 설명
    8~10분 피드백을 받은 모둠에서 "보완할 것 1가지" 토론

    활동 2: 전체 공유 (5분)¶

    시간이 허용되면 1~2명의 설계서를 전체에 공유합니다. 진행자가 다음을 질문합니다.

    "이 설계서에서 CT 4요소가 어떻게 연결되어 있는지 볼까요?"

    "분해한 하위 문제들이 알고리즘의 단계에 어떻게 반영되었나요?"

    "만약 이 설계서를 AI에게 주면, AI가 더 잘 도와줄 수 있을까요? 그냥 '해줘'라고 하는 것과 뭐가 다를까요?"

    진행자 팁: 마지막 질문은 5회차(Layer 2)로의 연결고리입니다. 학생들이 "설계서가 있으면 AI에게 시키기 편하겠다"는 생각을 하도록 유도하되, 이 시점에서 깊이 다루지는 않습니다. "바로 그 이야기를 다음 시간에 합니다"로 마무리하세요.

    진행자 팁: 피드백이 "잘했어요"나 "좋아요"처럼 막연해지기 쉽습니다. "체크리스트에서 체크하지 못한 항목이 있다면, 그것이 가장 중요한 피드백입니다"라고 안내하세요. 비판적 피드백이 더 값지다는 점을 강조합니다.

    진행자 팁: 학생들이 서로 피드백하는 것을 어색해할 수 있습니다. "여러분은 지금 '검증자' 역할을 하고 있습니다. 이것은 비판이 아니라, 설계서를 더 좋게 만들기 위한 '품질 검사'입니다"라고 프레이밍하세요.

    정리 (5분) — "Layer 1 완주, 그리고 새로운 시작"¶

    Layer 1 전체 회고¶

    "우리는 4회에 걸쳐 Computational Thinking의 4요소를 모두 경험했습니다."

    1회차: "AI 시대, 무엇이 남을까?" → CT의 필요성을 발견
2회차: "문제를 쪼개는 기술" → 분해(Decomposition) + MECE
3회차: "패턴 찾기와 핵심 추출" → 패턴 인식 + 추상화
4회차: "해결 절차 설계하기" → 알고리즘 설계 + CT 종합

    "1회차에는 '문제를 쪼개라'는 말이 낯설었을 수 있습니다. 지금은 어떤가요? 오늘 여러분이 작성한 CT 종합 설계서를 보세요. 문제를 정의하고, 쪼개고, 패턴을 찾고, 핵심을 추출하고, 해결 절차까지 설계했습니다. 4주 전에는 할 수 없었던 일입니다."

    오늘의 핵심 요약¶

    키워드 의미
    알고리즘 설계 문제를 해결하는 단계별 절차를 만드는 것
    순서도 절차를 시각적으로 표현하는 도구
    조건 분기 "만약 ~이면 A, 그렇지 않으면 B" — 상황에 따라 다른 행동
    반복 종료 조건이 충족될 때까지 일정 구간을 되풀이하는 것
    CT 종합 설계서 분해 + 패턴 인식 + 추상화 + 알고리즘 설계를 하나로 통합한 문서

    핵심 한 줄¶

    "문제를 쪼개고(분해), 비슷한 것을 찾고(패턴 인식), 핵심만 남기고(추상화), 순서를 정하면(알고리즘 설계) — 어떤 문제든 설계서로 만들 수 있다."

    Layer 2 예고¶

    "지금까지 우리는 AI를 한 번도 사용하지 않았습니다. 일부러 그랬습니다. AI를 쓰기 전에 '생각하는 힘' 자체를 먼저 갖추는 것이 중요하기 때문입니다."

    "다음 시간부터는 드디어 AI가 등장합니다. 하지만 AI에게 '해줘'라고 하는 것이 아닙니다. 여러분이 지금까지 쌓아온 구조적 사고력을 AI와 함께 사용하는 방법을 배울 겁니다."

    "예고를 하나 드리겠습니다. 같은 과제를 AI에게 시킬 때, '숙제 해줘'라고 하는 것과 오늘 작성한 것 같은 설계서를 주면서 시키는 것 — 결과가 얼마나 다를까요? 다음 시간에 직접 확인해봅시다."

    진행자 팁: Layer 2 예고는 기대감을 주되 구체적인 내용은 밝히지 않습니다. "다음 시간에 AI를 써본다"는 사실만으로 학생들의 흥미를 끌 수 있습니다. "오늘 쓴 설계서를 다음 시간에 가져오세요"라고 안내하면 자연스러운 연결이 됩니다.

    부록: 진행자를 위한 추가 안내¶

    시간 조절 가이드¶

    상황 조절 방법
    탐색이 길어질 때 모둠 공유를 3분으로 줄이고, 대표 1명만 발표
    실습이 부족할 때 공유와 검증에서 전체 공유를 생략하고 모둠 내 교환만 진행
    학생들이 빠르게 끝낼 때 Part E의 순서도 그리기에 시간을 더 할애하거나, 모둠원끼리 서로의 절차를 "실행"해보는 역할극 진행
    전체적으로 시간 초과 핵심 개념에서 '반복(Loop)' 부분을 간략히 언급만 하고 넘김

    "조건 분기가 없는 것 같아요" "정말요? 이 절차에서 상황이 달라지면 행동도 달라지는 부분이 하나도 없나요?"
    "순서도를 못 그리겠어요" "먼저 절차의 각 단계를 네모 상자로 나열하고, 화살표로 연결해보세요. 조건이 있는 곳만 마름모로 바꾸면 됩니다"
    "이걸 왜 해요? 코딩도 아닌데" "이것이 바로 AI에게 일을 시키기 전에 필요한 능력입니다. 다음 시간에 직접 확인해볼 거예요"
    "분해가 기억이 안 나요" "간단합니다. 큰 문제를 작은 문제로 쪼개는 거예요. 2회차 워크시트를 참고해보세요"
    "이미 다 했어요" (빠른 학생) "좋습니다! 그럼 모둠원 중 한 명의 설계서를 먼저 검증해줄 수 있나요?"

    평가 관점¶

    이 회차의 평가는 결과물의 완성도가 아니라 사고의 구조화 과정에 초점을 맞춥니다.

    평가 요소 관찰 포인트
    CT 4요소 적용 4가지 요소가 설계서에 모두 포함되어 있는가?
    논리적 일관성 분해한 하위 문제가 알고리즘의 단계에 반영되어 있는가?
    구체성 "공부한다" 수준이 아니라 "수학 2단원 개념 문제 10개를 풀고 채점한다" 수준인가?
    조건 분기 활용 상황에 따라 다른 행동을 하는 분기가 포함되어 있는가?
    피드백 능력 다른 모둠의 설계서를 검증할 때 구체적인 피드백을 제공했는가?

    이 회차와 다른 회차의 연결¶

    연결 방향 내용
    2회차에서 가져오는 것 분해(Decomposition)와 MECE 원칙 — Part B에서 직접 적용
    3회차에서 가져오는 것 패턴 인식과 추상화 — Part C, D에서 직접 적용
    5회차로 보내는 것 "AI에게 시키는 3가지 수준" — 오늘의 설계서가 수준 3(시스템 설계)의 기초가 됨
    6회차로 보내는 것 "AI 협업 설계서" — CT 종합 설계서의 구조가 AI 협업 설계서로 발전함

    부록: CT 종합 설계서 작성 예시 (전체)¶

    이 예시는 교사가 참고하기 위한 것입니다. 학생에게는 실습 중 막히는 경우에만 부분적으로 보여주세요.

    문제: "중간고사 2주 전, 7과목을 효율적으로 준비하는 방법"¶

    Part A. 문제 정의

    • 문제: "나는 중간고사 2주 전에 7과목(국어, 수학, 영어, 과학, 사회, 한국사, 정보)을 효율적으로 준비하는 문제를 해결하고 싶다."
    • 어려운 이유:
    • 과목이 많아서 무엇부터 해야 할지 막막하다
    • 과목마다 공부 방법이 다르다 (암기 vs 이해 vs 연습)
    • 시간은 한정되어 있는데 해야 할 양이 많다
    • 성공 기준: "모든 과목에서 평균 80점 이상을 받고, 시험 전날 밤샘을 하지 않는 상태"

    Part B. 분해

    • 하위 문제 1: 각 과목의 현재 이해도 파악
    • 하위 문제 2: 과목별 공부 분량 산정
    • 하위 문제 3: 2주 일정표 작성
    • 하위 문제 4: 과목별 공부 방법 결정
    • 하위 문제 5: 진도 점검 및 일정 조정
    • 분해 기준: "시간 순서 + 과목별 특성"
    • MECE 점검: 모든 과목이 포함됨, 하위 문제 간 중복 없음

    Part C. 패턴 인식

    • "이 문제는 '여행 계획 세우기'와 구조가 비슷하다. 둘 다 '현재 상태 파악 → 자원(시간/돈) 산정 → 일정 배분 → 실행 중 조정' 패턴을 공유한다."
    • 여행 계획에서 효과적이었던 '우선순위 정하기'를 시험 준비에도 적용할 수 있다

    Part D. 추상화

    • 핵심 요소: (1) 과목별 이해도 수준 (2) 가용 시간 (3) 공부 방법(암기/이해/연습)
    • 비핵심: 공부 장소, 필기구 종류, 간식
    • 핵심 원칙: "이해도가 낮은 과목에 시간을 더 배분하되, 암기 과목은 시험 직전에 집중한다"

    Part E. 알고리즘 설계

    1단계: 7과목 각각에 대해 현재 이해도를 상/중/하로 자가 평가한다

2단계: 이해도 "하" 과목을 우선순위 A, "중"을 B, "상"을 C로 분류한다

3단계: 과목별 공부 방법을 결정한다
  - 만약 암기 과목(한국사, 사회 등)이면 → 반복 읽기 + 키워드 정리
  - 만약 이해 과목(수학, 과학 등)이면 → 개념 정리 + 문제 풀기
  - 만약 혼합 과목(국어, 영어 등)이면 → 개념 정리 + 암기 + 문제 풀기

4단계: 2주(14일) 일정표를 작성한다
  - 1주차(D-14~D-8): 우선순위 A 과목 집중 + B 과목 시작
  - 2주차 전반(D-7~D-4): B 과목 집중 + A 과목 복습
  - 2주차 후반(D-3~D-1): 암기 과목 집중 + 전 과목 최종 정리
  - 하루 공부 시간: 평일 3시간, 주말 5시간

5단계: 매일 저녁 10분간 진도 점검
  - 만약 계획 대비 80% 이상 완료 → 다음 날 계획대로 진행
  - 만약 80% 미만 완료 → 일정 재조정 (덜 급한 C 과목 시간 줄이기)
  → 5단계를 시험 전날까지 매일 반복

6단계: 시험 전날 — 전 과목 핵심 노트 1회 훑기

7단계: 시험 당일 — 해당 과목 핵심 키워드만 10분 복습

    부록: 다음 회차(5회차) 연결 브릿지¶

    4회차에서 5회차로의 전환은 이 과정에서 가장 중요한 전환점입니다. Layer 1(AI 없이 생각하는 힘)에서 Layer 2(AI와 함께 생각하는 힘)로 넘어가는 순간이기 때문입니다.

    연결 논리¶

    Layer 1에서 쌓은 것                Layer 2에서 활용하는 방식
─────────────────────────────────────────────────────────────
문제를 분해하는 능력         →    AI에게 구조적으로 지시하기
패턴을 인식하는 능력         →    AI가 발견한 패턴을 검증하기
핵심을 추출하는 능력         →    AI 결과물에서 핵심을 판단하기
절차를 설계하는 능력         →    AI 활용 시스템(Harness) 설계하기

    "여러분이 4회차에 걸쳐 쌓아온 이 능력은, 사실 AI를 '잘' 사용하기 위한 필수 전제조건이었습니다. AI 없이도 문제를 구조적으로 사고할 수 있는 사람만이, AI와의 협업에서 주도권을 유지할 수 있습니다."

    5회차 준비 사항¶

    • 학생들에게 "오늘 작성한 CT 종합 설계서를 다음 시간에 가져오세요"라고 안내합니다
    • 5회차에서 같은 문제를 AI에게 시켜보며, 설계서가 있을 때와 없을 때의 차이를 직접 체험합니다
    • 이 경험이 "AI 활용의 3가지 수준"을 체감하는 핵심 활동이 됩니다
