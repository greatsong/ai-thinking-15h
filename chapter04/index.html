    Layer 1 --- 구조적 사고력

    4회차: 해결 절차 설계하기

    CT 4요소(분해, 패턴 인식, 추상화, 알고리즘 설계)를 통합하여 하나의 완전한 설계서를 만드는 시간입니다. Layer 1의 마지막 회차로, 여기서 쌓은 구조적 사고력이 이후 AI 협업의 기반이 됩니다.

    **이 회차를 마치면 여러분은 다음을 할 수 있습니다.** 1. **알고리즘 설계(Algorithm Design)**의 개념을 이해하고 절차적 사고를 적용할 수 있다 2. **CT 4요소(분해, 패턴 인식, 추상화, 알고리즘 설계)**를 통합하여 하나의 완전한 설계서를 작성할 수 있다 3. 다른 사람의 설계서를 **검증 체크리스트**로 평가하고 건설적 피드백을 제공할 수 있다

    📌 이 회차의 위치와 의미¶

    4회차는 Layer 1의 마무리이자 종합입니다. 지난 3회차에 걸쳐 하나씩 익힌 CT 4요소를 이번에 처음으로 하나의 완결된 설계서로 통합해 봅니다.

    회차 핵심 내용
    1회차 CT 전체 조감 + 분해 첫 경험
    2회차 분해(Decomposition) 심화 + MECE
    3회차 패턴 인식(Pattern Recognition) + 추상화(Abstraction)
    4회차 알고리즘 설계(Algorithm Design) + CT 4요소 종합
    5회차~ Layer 2 --- 이 사고력을 AI와 함께 사용합니다

    이 회차가 끝나면 여러분은 "문제를 구조적으로 사고하는 프레임워크"를 갖추게 됩니다. 다음 회차부터는 AI가 등장하지만, AI에게 좋은 지시를 내리려면 이 프레임워크가 반드시 필요합니다. 그래서 4회차는 Layer 1의 종착점이자 Layer 2로 가는 다리 역할을 합니다.

    이 회차에서 AI 도구는 사용하지 않습니다. Layer 1의 마지막 AI-free 회차입니다.

    🎬 도입 --- "재료는 준비됐는데, 순서가 없다"¶

    1~3회차 빠른 복습¶

    지난 세 번의 학습에서 여러분은 세 가지 강력한 도구를 익혔습니다.

    1회차 --- 분해
    큰 문제를 작은 문제로 쪼개기
    2회차 --- 분해 심화
    MECE로 빠짐없이, 겹침없이
    3회차 --- 패턴 인식 + 추상화
    공통 구조 발견 + 핵심만 남기기
    4회차 --- 알고리즘 설계
    해결 절차를 단계별로 구성하기 (오늘!)

    이 세 가지를 모두 잘한다고 가정해 봅시다. 문제를 쪼갰고, 패턴도 찾았고, 핵심도 뽑아냈습니다. 그런데... 뭔가 빠진 것 같지 않나요?

    맞습니다. 순서가 없습니다. 이걸 어떤 순서로 실행해야 할까요?

    요리 레시피 비유¶

    요리를 생각해 봅시다. 볶음밥을 만든다고 해볼까요?

    • 재료 준비 (분해): 밥, 달걀, 파, 간장, 기름
    • 조리 패턴 (패턴 인식): 대부분의 볶음 요리는 '기름 두르기 → 센 불에 볶기 → 양념 넣기' 패턴을 따릅니다
    • 핵심 원리 (추상화): "볶음의 핵심은 높은 온도에서 빠르게 수분을 날리는 것"

    재료도 있고, 패턴도 알고, 원리도 이해했습니다. 그런데 달걀을 먼저 볶아야 할까요, 밥을 먼저 넣어야 할까요? 간장은 언제 넣어야 할까요?

    이 '순서'를 정하는 것, 그것이 바로 오늘 배울 알고리즘 설계입니다.

    요소 볶음밥에서의 역할
    재료 (분해) 밥, 달걀, 파, 간장, 기름
    조리법 (패턴) 기름 → 센 불 → 양념
    핵심 원리 (추상화) 높은 온도에서 수분을 날린다
    순서 (알고리즘) 기름 → 달걀 → 밥 → 파 → 간장

    이 네 가지가 모여야 비로소 '누구나 따라 할 수 있는 레시피'가 됩니다. 오늘 여러분은 이 마지막 퍼즐 조각을 채우고, 네 가지를 합쳐서 하나의 완전한 설계서를 만들어 볼 겁니다.

    🔍 탐색 --- "먼저 절차를 설계해보자"¶

    지금부터 여러분이 직접 '절차'를 설계해 봅니다. 어렵게 생각하지 마세요. 우리는 이미 매일 절차를 따르며 살고 있습니다.

    활동 1: 개인 탐색¶

    다음 두 가지 문제 중 하나를 선택하여 해결 절차를 단계별로 적어 봅니다.

    문제 A: 학교 가는 최적 경로

    집에서 학교까지 가는 가장 효율적인 방법을 설계하세요. 단, 다음 조건을 고려해야 합니다.

    • 날씨 (비가 오는 날 vs 맑은 날)
    • 시간 (여유 있는 날 vs 늦잠 잔 날)
    • 준비물 (체육복이 있는 날 vs 없는 날)

    문제 B: 시험 전날 공부 순서

    내일 수학, 영어, 과학 시험이 있습니다. 오늘 저녁 4시간 동안 공부해야 합니다. 어떤 순서로, 각각 얼마나 공부할 것인지 절차를 설계하세요.

    • 수학: 이해는 됐지만 연습이 부족
    • 영어: 단어 암기가 필요
    • 과학: 개념 자체가 헷갈림

    각자 노트나 메모장에 번호를 붙여서 단계별로 적어 봅시다.

    **절차 설계 연습** - 1단계: ____________________________________________ - 2단계: ____________________________________________ - 3단계: ____________________________________________ - (만약 ____이면) → ____________________________________________ - (그렇지 않으면) → ____________________________________________ - 4단계: ____________________________________________ - ...

    활동 2: 비교와 성찰¶

    작성한 절차를 되짚어보며, 다음 질문들을 스스로에게 던져 보세요.

    비교 질문
    • 같은 문제를 다른 사람이 풀었다면 절차가 다를 수 있을까요? 왜 다를까요?
    • 내 절차에서 '만약 ~이면' 같은 조건이 들어간 부분이 있나요?
    • 이 절차를 모르는 사람에게 주면, 그대로 따라 할 수 있을까요?
    핵심 발견 질문
    • 절차를 정할 때 가장 어려웠던 부분은 무엇인가요?
    • 순서를 바꾸면 결과가 달라지는 경우가 있었나요?

    절차가 너무 단순하다면?

    "1. 공부한다 2. 잔다"처럼 적었다면, 1단계인 '공부한다'를 좀 더 구체적으로 쪼개볼 수 있을까요? 어떤 과목을, 어떤 방법으로, 얼마나? 이것 자체가 분해(Decomposition)의 복습입니다.

    '만약 ~이면'이 자연스럽게 나왔다면?

    축하합니다! 그것이 바로 다음 단계에서 배울 조건 분기입니다. "만약 비가 오면 버스, 안 오면 자전거" --- 이것에 이름이 있습니다.

    📌 핵심 개념 --- "절차에도 문법이 있다"¶

    알고리즘 설계란?¶

    방금 여러분이 한 것, 그것이 알고리즘 설계(Algorithm Design)입니다.

    알고리즘이라고 하면 프로그래밍이나 수학이 떠오를 수 있지만, 원래 의미는 훨씬 단순합니다. 문제를 해결하는 단계별 절차를 만드는 것입니다. 요리 레시피, 조립 설명서, 대피 매뉴얼 --- 이 모든 것이 알고리즘입니다.

    좋은 알고리즘은 **다른 사람이 이 절차만 보고 따라 해도 같은 결과를 얻을 수 있는 것**입니다.

    알고리즘의 세 가지 조건을 확인해 봅시다.

    조건 의미 예시
    명확성 각 단계가 모호하지 않아야 한다 "적당히 볶는다" (X) → "중불에서 3분 볶는다" (O)
    순서 단계의 순서가 정해져 있어야 한다 간장을 언제 넣느냐에 따라 맛이 달라진다
    종료 언젠가는 끝나야 한다 "완벽해질 때까지 반복" (X) → "3회 반복 후 마무리" (O)

    순서도 그리기 기초¶

    절차를 글로만 적으면 복잡해지기 쉽습니다. 그래서 순서도(Flowchart)라는 도구를 사용합니다. 기본 기호는 다음과 같습니다.

    ┌─────────────┐
│   시작/끝    │    ← 둥근 모서리: 시작과 끝
└─────────────┘

┌─────────────┐
│   처리 단계   │    ← 직사각형: 실행하는 행동
└─────────────┘

      ◇
     / \
    /   \          ← 마름모: 조건 판단 (예/아니오)
   /     \
  ◇───────◇

      │
      ↓             ← 화살표: 흐름의 방향

    순서도는 코딩이 아닙니다

    프로그래밍을 모르는 사람도 순서도는 읽을 수 있습니다. 이것은 코딩이 아니라 사고를 시각화하는 도구입니다. 설계가 좋으면 코딩은 AI가 대신 해줄 수 있지만, 설계는 여러분이 해야 합니다.

    조건 분기(if-then)의 등장¶

    순서도에서 가장 강력한 것은 마름모, 즉 조건 분기입니다. 학교 가는 길 예시로 살펴봅시다.

        [시작: 등교 준비 완료]
            │
            ↓
      ◇ 비가 오는가? ◇
      │              │
    [예]            [아니오]
      │              │
      ↓              ↓
  [버스 타기]    ◇ 시간 여유? ◇
      │          │           │
      │        [예]        [아니오]
      │          │           │
      │          ↓           ↓
      │     [자전거]    [지하철]
      │          │           │
      └────┬─────┘───────────┘
           │
           ↓
      [학교 도착]

    비가 오면 무조건 버스. 비가 안 오면 시간 여유에 따라 자전거 또는 지하철. 이것이 조건 분기입니다. 프로그래밍에서는 if-then-else라고 부르지만, 우리가 일상에서 매순간 하는 판단이 바로 이것입니다.

    한 걸음 더: 반복(Loop)¶

    절차에는 '조건 분기' 말고도 반복이 있습니다.

        [시험 공부 시작]
          │
          ↓
    [문제 1개 풀기]
          │
          ↓
    ◇ 정답인가? ◇
    │           │
  [예]        [아니오]
    │           │
    │     [오답 노트 정리]
    │           │
    └─────┬─────┘
          │
          ↓
    ◇ 30분 지났는가? ◇
    │                │
  [예]             [아니오]
    │                │
    ↓            [처음으로 ↑]
  [다음 과목으로]

    문제를 풀고, 틀리면 오답 노트를 정리하고, 30분이 안 됐으면 다시 문제를 풀고... 이 '돌아가기'가 반복입니다. 반복에는 반드시 종료 조건(여기서는 '30분')이 있어야 합니다. 그렇지 않으면 영원히 끝나지 않습니다.

    CT 4요소 종합 정리¶

    이제 여러분은 Computational Thinking의 4요소를 모두 배웠습니다.

    [1] 분해 (Decomposition)
    "큰 문제를 작은 문제로 쪼갠다"
    → 2회차에서 MECE 원칙까지 배웠습니다
    [2] 패턴 인식 (Pattern Recognition)
    "서로 다른 문제에서 공통 구조를 찾는다"
    → 3회차에서 여러 문제의 공통 패턴을 발견했습니다
    [3] 추상화 (Abstraction)
    "핵심만 남기고 불필요한 세부사항을 걸러낸다"
    → 3회차에서 핵심 추출 연습을 했습니다
    [4] 알고리즘 설계 (Algorithm Design)
    "해결 절차를 단계별로 구성한다"
    → 순서, 조건 분기, 반복을 포함하는 절차 설계 (오늘!)

    각 요소가 어떻게 연결되는지, 비유로 정리해 봅시다.

    CT 요소 건축 비유 요리 비유 시험 준비 비유
    분해 건물을 층별/구역별로 나누기 재료를 종류별로 분류하기 과목별/단원별로 나누기
    패턴 인식 반복되는 층 구조 발견 볶음 요리의 공통 패턴 암기 과목 vs 이해 과목 패턴
    추상화 핵심 구조(골조)만 남기기 "높은 온도 + 빠른 조리" 원리 "개념 이해가 안 된 과목 먼저" 원칙
    알고리즘 설계 공사 순서와 일정표 조리 순서(레시피) 공부 순서와 시간 배분
    1~3회차에서 재료를 준비하고 패턴을 찾고 핵심을 뽑아냈습니다. 오늘 '순서'를 더하면, 드디어 **누구에게 주어도 실행할 수 있는 완전한 설계서**가 됩니다.

    🛠️ 실습 --- "CT 종합 설계서 작성"¶

    오늘의 실습은 Layer 1의 최종 산출물입니다. 지금까지 배운 CT 4요소를 모두 적용하여, 여러분이 직접 선택한 문제에 대한 완전한 설계서를 작성합니다.

    중요한 기준

    중요한 것은 결과의 '정답'이 아닙니다. 네 가지 요소가 빠짐없이 적용되었는지, 그리고 이 설계서를 다른 사람이 보고 실행할 수 있는지가 기준입니다.

    문제 선택¶

    아래 보기에서 문제를 하나 선택하거나, 자신만의 문제를 정해 보세요. 스스로 문제를 정하는 것이 가장 좋습니다.

    영역 문제 예시
    학교생활 "중간고사 2주 전, 7과목을 효율적으로 준비하는 방법"
    학교생활 "학급 발표 자료를 체계적으로 준비하는 방법"
    동아리/행사 "학교 축제 부스 운영을 기획하는 방법"
    동아리/행사 "동아리 신입 부원 모집을 효과적으로 진행하는 방법"
    일상생활 "3박 4일 수학여행 짐 싸기를 빠짐없이 하는 방법"
    일상생활 "용돈을 한 달 동안 계획적으로 관리하는 방법"
    자유 선택 자신이 최근 해결하고 싶었던 문제 아무거나

    워크시트: CT 종합 설계서¶

    #### CT 종합 설계서 (Layer 1 최종 산출물) **이름**: __________________ **날짜**: __________________ --- **Part A. 문제 정의** **[A-1]** 내가 해결하고 싶은 문제 (한 문장) > "나는 ________________________________________________ 문제를 해결하고 싶다." **[A-2]** 이 문제가 왜 어려운가? (성공 기준) > "이 문제가 해결되면 ________________________________________________ 상태가 된다." --- **Part B. 분해 (Decomposition) --- 2회차 복습 적용** **[B-1]** 하위 문제로 분해 (최소 3개, 최대 6개) - 하위 문제 1: ____________________________________________ - 하위 문제 2: ____________________________________________ - 하위 문제 3: ____________________________________________ - 하위 문제 4: ____________________________________________ - 하위 문제 5: ____________________________________________ - 하위 문제 6: ____________________________________________ **[B-2]** 분해 기준 > "나는 ________________ 기준으로 문제를 나누었다. 그 이유는 ____________________________________________" **[B-3]** MECE 점검 - [ ] 하위 문제를 모두 해결하면 원래 문제가 해결되는가? (포괄성) - [ ] 하위 문제끼리 겹치는 부분이 없는가? (배타성) - 빠뜨린 것이 있다면: ____________________________________ --- **Part C. 패턴 인식 (Pattern Recognition) --- 3회차 복습 적용** **[C-1]** 이 문제와 비슷한 구조의 문제가 있는가? > "이 문제는 ________________________________ 와(과) 구조가 비슷하다. 왜냐하면 둘 다 ________________________________ 패턴을 공유하기 때문이다." **[C-2]** 그 패턴으로부터 배울 수 있는 것 > "비슷한 문제에서 효과적이었던 방법은 ____________________. 이 방법을 내 문제에도 적용할 수 있다 / 적용할 수 없다. 그 이유는 ____________________________________________" --- **Part D. 추상화 (Abstraction) --- 3회차 복습 적용** **[D-1]** 이 문제에서 가장 핵심적인 요소 3가지 1. ________________________________________________ 2. ________________________________________________ 3. ________________________________________________ **[D-2]** 무시해도 되는 세부사항 (지금 단계에서 안 중요한 것) 1. ________________________________________________ 2. ________________________________________________ **[D-3]** 핵심 원칙 한 줄 > "이 문제의 핵심 원칙은 '________________________________________________' 이다." --- **Part E. 알고리즘 설계 (Algorithm Design) --- 오늘의 핵심!** **[E-1]** 해결 절차 (번호를 붙여 단계별로 작성) 1. ________________________________________________ 2. ________________________________________________ 3. ________________________________________________ - 만약 ________________ 이면 → ________________________ - 그렇지 않으면 → ____________________________________ 4. ________________________________________________ 5. ________________________________________________ 6. ________________________________________________ 7. ________________________________________________ (단계는 자유롭게 추가하거나 줄여도 됩니다) **[E-2]** 조건 분기가 필요한 곳 (위 절차에서 "만약 ~이면" 부분) - 조건 1: "만약 ________________________ 이면" - 예: ____________________________________________ - 아니오: ________________________________________ - 조건 2: "만약 ________________________ 이면" - 예: ____________________________________________ - 아니오: ________________________________________ **[E-3]** 반복이 필요한 곳 (돌아가서 다시 해야 하는 부분) > "_____ 단계 ~ _____ 단계를 ________________________ 될 때까지 반복한다." > > 종료 조건: ____________________________________________ **[E-4]** 간단한 순서도 그리기 아래 빈 공간에 시작 → 처리 → 조건 → 끝의 흐름을 그려 보세요. (노트나 종이에 자유롭게 그립니다) --- **Part F. 자기 검증** 아래 항목을 스스로 점검하세요. - [ ] 문제가 한 문장으로 명확하게 정의되었는가? (Part A) - [ ] 하위 문제가 MECE 원칙을 만족하는가? (Part B) - [ ] 비슷한 문제의 패턴을 활용했는가? (Part C) - [ ] 핵심과 비핵심을 구분했는가? (Part D) - [ ] 절차에 조건 분기가 포함되어 있는가? (Part E) - [ ] 이 설계서대로 실행하면 문제가 해결될 것 같은가? - [ ] 이 설계서를 나 말고 다른 사람이 보고 따라 할 수 있는가? 체크하지 못한 항목이 있으면 해당 Part로 돌아가서 보완하세요.

    실습 가이드¶

    시간 배분 팁

    • Part A~D는 이미 2~3회차에서 연습한 내용이므로 비교적 빠르게 진행됩니다.
    • 시간의 절반 이상을 Part E(알고리즘 설계)에 쓰세요. 오늘의 핵심입니다.
    • "조건 분기 하나는 꼭 포함하세요." 정말 아무런 판단이 필요 없는 문제인가요? 어떤 상황이 달라지면 행동도 달라지는 경우가 없나요?

    순서도(E-4)에서 막힌다면?

    먼저 E-1의 절차를 네모 상자로 나열하고, 조건 분기 부분만 마름모로 바꿔보세요. 순서도가 완벽할 필요는 없습니다. 핵심은 '절차를 시각화하려는 시도' 자체입니다.

    작성 예시 (참고용)¶

    예시: 학급 발표 자료를 체계적으로 준비하는 방법

    Part B (분해): 주제 선정 / 자료 조사 / 구조 설계 / 자료 제작 / 발표 연습

    Part C (패턴): "이것은 독서감상문 쓰기와 비슷하다. 둘 다 '주제 → 자료 수집 → 구조화 → 표현' 패턴을 따른다."

    Part D (추상화): 핵심은 "전달하고 싶은 메시지를 명확히 하고, 그것을 뒷받침하는 근거를 구조화하는 것". 폰트 종류나 애니메이션 효과는 비핵심.

    Part E (알고리즘):

    1. 발표 주제 정하기
    2. 핵심 메시지 한 문장으로 정리
    3. 뒷받침 근거 3가지 조사
      • 만약 근거가 3가지 안 되면 → 주제 범위 넓히기
      • 3가지 이상이면 → 가장 강력한 3가지 선택
    4. 슬라이드 구조 잡기 (서론-본론1-본론2-본론3-결론)
    5. 슬라이드 제작
    6. 발표 연습 (타이머 사용)
      • 만약 시간 초과면 → 내용 축소 후 6번 반복
      • 시간 적정이면 → 7번으로
    7. 최종 점검

    설계서 교환 검증¶

    다른 사람과 CT 종합 설계서를 교환해 봅시다. 받은 설계서를 다음 종합 검증 체크리스트로 평가합니다. 혼자 학습 중이라면, 하루 지난 뒤 자기 설계서를 다시 읽으며 아래 기준으로 점검해 보세요.

    #### CT 종합 설계서 --- 종합 검증 체크리스트 **작성자**: ______________ **검증자**: ______________ **문제 정의 (Part A)** - [ ] 문제가 한 문장으로 명확하게 정의되어 있는가? - [ ] 성공 기준이 구체적인가? (모호한 표현이 아닌가?) **분해 (Part B)** - [ ] 하위 문제가 최소 3개 이상인가? - [ ] 하위 문제를 모두 해결하면 원래 문제가 해결되는가? (포괄성) - [ ] 하위 문제끼리 겹치는 부분이 없는가? (배타성) - [ ] 분해 기준이 납득되는가? **패턴 인식 (Part C)** - [ ] 비슷한 구조의 다른 문제를 찾았는가? - [ ] 그 패턴에서 배운 점이 명확한가? **추상화 (Part D)** - [ ] 핵심 요소와 비핵심 요소가 구분되어 있는가? - [ ] 핵심 원칙이 이 문제의 본질을 잘 표현하는가? **알고리즘 설계 (Part E)** --- 가장 중요! - [ ] 절차가 단계별로 명확한가? - [ ] 조건 분기("만약 ~이면")가 적어도 1개 포함되어 있는가? - [ ] 각 단계가 구체적인가? (모호한 단계가 없는가?) - [ ] 이 절차대로 실행하면 문제가 실제로 해결될 것 같은가? - [ ] 나(검증자)가 이 설계서만 보고 따라 할 수 있는가? **종합 평가** CT 4요소가 모두 포함되어 있는가? - [ ] 분해 - [ ] 패턴 인식 - [ ] 추상화 - [ ] 알고리즘 설계 이 설계서의 가장 좋은 점: ________________________________________________________ 이 설계서에서 보완하면 좋을 점: ________________________________________________________ 한 줄 피드백: "________________________________________________________"

    피드백 관점

    "잘했어요"나 "좋아요"처럼 막연한 피드백보다는, 체크리스트에서 체크하지 못한 항목이 가장 중요한 피드백입니다. 비판적 피드백이 설계서를 더 좋게 만듭니다. 이것은 비판이 아니라, 설계서의 품질 검사입니다.

    📖 정리 --- "Layer 1 완주, 그리고 새로운 시작"¶

    Layer 1 전체 회고¶

    4회에 걸쳐 Computational Thinking의 4요소를 모두 경험했습니다.

    회차 주제 배운 것
    1회차 "AI 시대, 무엇이 남을까?" CT의 필요성을 발견
    2회차 "문제를 쪼개는 기술" 분해(Decomposition) + MECE
    3회차 "패턴 찾기와 핵심 추출" 패턴 인식 + 추상화
    4회차 "해결 절차 설계하기" 알고리즘 설계 + CT 종합

    1회차에는 '문제를 쪼개라'는 말이 낯설었을 수 있습니다. 지금은 어떤가요? 오늘 작성한 CT 종합 설계서를 다시 보세요. 문제를 정의하고, 쪼개고, 패턴을 찾고, 핵심을 추출하고, 해결 절차까지 설계했습니다. 처음에는 할 수 없었던 일입니다.

    오늘의 핵심 요약¶

    키워드 의미
    알고리즘 설계 문제를 해결하는 단계별 절차를 만드는 것
    순서도 절차를 시각적으로 표현하는 도구
    조건 분기 "만약 ~이면 A, 그렇지 않으면 B" --- 상황에 따라 다른 행동
    반복 종료 조건이 충족될 때까지 일정 구간을 되풀이하는 것
    CT 종합 설계서 분해 + 패턴 인식 + 추상화 + 알고리즘 설계를 하나로 통합한 문서

    핵심 한 줄¶

    "문제를 쪼개고(분해), 비슷한 것을 찾고(패턴 인식), 핵심만 남기고(추상화), 순서를 정하면(알고리즘 설계) --- 어떤 문제든 설계서로 만들 수 있다."

    부록: CT 종합 설계서 작성 예시 (전체)¶

    이 예시는 스스로 작성할 때 막히는 경우 참고용으로 활용하세요.

    예시: 중간고사 2주 전, 7과목을 효율적으로 준비하는 방법

    Part A. 문제 정의

    • 문제: "나는 중간고사 2주 전에 7과목(국어, 수학, 영어, 과학, 사회, 한국사, 정보)을 효율적으로 준비하는 문제를 해결하고 싶다."
    • 어려운 이유:
      1. 과목이 많아서 무엇부터 해야 할지 막막하다
      2. 과목마다 공부 방법이 다르다 (암기 vs 이해 vs 연습)
      3. 시간은 한정되어 있는데 해야 할 양이 많다
    • 성공 기준: "모든 과목에서 평균 80점 이상을 받고, 시험 전날 밤샘을 하지 않는 상태"

    Part B. 분해

    • 하위 문제 1: 각 과목의 현재 이해도 파악
    • 하위 문제 2: 과목별 공부 분량 산정
    • 하위 문제 3: 2주 일정표 작성
    • 하위 문제 4: 과목별 공부 방법 결정
    • 하위 문제 5: 진도 점검 및 일정 조정
    • 분해 기준: "시간 순서 + 과목별 특성"
    • MECE 점검: 모든 과목이 포함됨, 하위 문제 간 중복 없음

    Part C. 패턴 인식

    • "이 문제는 '여행 계획 세우기'와 구조가 비슷하다. 둘 다 '현재 상태 파악 → 자원(시간/돈) 산정 → 일정 배분 → 실행 중 조정' 패턴을 공유한다."
    • 여행 계획에서 효과적이었던 '우선순위 정하기'를 시험 준비에도 적용할 수 있다

    Part D. 추상화

    • 핵심 요소: (1) 과목별 이해도 수준 (2) 가용 시간 (3) 공부 방법(암기/이해/연습)
    • 비핵심: 공부 장소, 필기구 종류, 간식
    • 핵심 원칙: "이해도가 낮은 과목에 시간을 더 배분하되, 암기 과목은 시험 직전에 집중한다"

    Part E. 알고리즘 설계

    1단계: 7과목 각각에 대해 현재 이해도를 상/중/하로 자가 평가한다
2단계: 이해도 "하" 과목을 우선순위 A, "중"을 B, "상"을 C로 분류한다
3단계: 과목별 공부 방법을 결정한다
  - 만약 암기 과목(한국사, 사회 등)이면 → 반복 읽기 + 키워드 정리
  - 만약 이해 과목(수학, 과학 등)이면 → 개념 정리 + 문제 풀기
  - 만약 혼합 과목(국어, 영어 등)이면 → 개념 정리 + 암기 + 문제 풀기
4단계: 2주(14일) 일정표를 작성한다
  - 1주차(D-14~D-8): 우선순위 A 과목 집중 + B 과목 시작
  - 2주차 전반(D-7~D-4): B 과목 집중 + A 과목 복습
  - 2주차 후반(D-3~D-1): 암기 과목 집중 + 전 과목 최종 정리
  - 하루 공부 시간: 평일 3시간, 주말 5시간
5단계: 매일 저녁 10분간 진도 점검
  - 만약 계획 대비 80% 이상 완료 → 다음 날 계획대로 진행
  - 만약 80% 미만 완료 → 일정 재조정 (덜 급한 C 과목 시간 줄이기)
  → 5단계를 시험 전날까지 매일 반복
6단계: 시험 전날 — 전 과목 핵심 노트 1회 훑기
7단계: 시험 당일 — 해당 과목 핵심 키워드만 10분 복습
