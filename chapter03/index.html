    3회차: 패턴 찾기와 핵심 추출¶

    서로 다른 문제에서 같은 구조를 발견하고, 추상화로 핵심만 남기는 연습을 합니다.

    90분 Layer 1 — 3/4 AI 도구 미사용

    🎯 학습 목표¶

    이 강의를 마치면 여러분은 다음을 할 수 있게 됩니다.

    1. 서로 다른 문제들에서 반복되는 공통 구조(패턴)를 발견할 수 있다
    2. 추상화(Abstraction)를 적용하여 핵심 요소만 추출하고 불필요한 세부사항을 걸러낼 수 있다
    3. 패턴 인식과 추상화를 자신의 실제 문제에 적용할 수 있다

    🎬 도입 — 지난 시간 복습에서 오늘로¶

    2회차에서 배운 것¶

    지난 시간에 우리는 분해(Decomposition)를 배웠습니다. 큰 문제를 작은 문제로 나누면 갑자기 해결 가능해지는 경험을 했고, MECE 원칙으로 "빠진 건 없는가, 겹치는 건 없는가"를 점검하는 방법도 연습했습니다.

    스스로 확인해 보세요

    지난 시간에 분해한 문제를 떠올려 보세요. 혹시 이번 주에 일상에서 "이건 분해하면 쉬워지겠다"라고 느낀 순간이 있었나요? 잠깐 생각해 보고, 있다면 메모해 두세요.

    패턴의 힘 — "수학에서 공식은 왜 유용한가?"¶

    한 가지 질문으로 시작해 봅시다.

    수학에서 공식이 왜 유용할까요?

    삼각형의 넓이를 구한다고 합시다. 처음에는 하나하나 세어볼 수 있어요. 그런데 삼각형을 100개 풀어보면 어떤 일이 일어나나요? "아, 밑변 곱하기 높이 나누기 2구나!"라는 공식을 발견하게 됩니다. 그러면 101번째 삼각형부터는 순식간에 풀 수 있죠.

    이것이 바로 패턴의 힘입니다. 같은 유형의 문제를 여러 번 경험하면, 그 안에 숨어 있는 공통 구조가 보입니다. 그리고 그 공통 구조를 한 번 잡아내면, 새로운 문제도 빠르게 풀 수 있게 됩니다.

    오늘은 지난 시간의 "분해"에 이어서, 패턴 인식과 추상화라는 두 가지 사고 도구를 배웁니다.

    • 분해 = 문제를 쪼개는 기술
    • 패턴 인식 = 쪼갠 것들 속에서 반복을 찾는 기술
    • 추상화 = 핵심만 남기는 기술

    공식을 외우는 것 vs. 패턴을 발견하는 것

    오늘은 공식을 외우는 시간이 아닙니다. 공식이 어떻게 만들어지는지를 경험하는 시간입니다. 누군가 알려준 규칙을 외우는 것과, 스스로 규칙을 발견하는 것은 완전히 다른 능력이에요.

    일상 속 패턴¶

    일상에서도 패턴은 늘 작동하고 있어요. 학교에 처음 전학 왔을 때를 생각해 보세요. 처음에는 모든 게 새롭고 복잡하지만, 일주일쯤 지나면 "아, 월요일 1교시는 수학이고, 점심시간에는 매점이 붐비고, 5교시 후에는 청소 시간이구나"라는 패턴이 보이기 시작합니다. 패턴이 보이면 학교생활이 훨씬 수월해지죠.

    🔍 탐색 — 세 가지 문제를 비교해 봅시다¶

    지금부터 세 가지 서로 다른 문제를 살펴보겠습니다. 전혀 다른 상황처럼 보이지만, 잘 들여다보면 놀라운 공통점이 있을 수 있습니다. 먼저 혼자 생각해 보세요.

    세 가지 문제¶

    문제 A: 학교 축제 기획

    우리 반이 학교 축제에서 부스를 운영하기로 했습니다. 메뉴 선정, 재료 구매, 역할 분담, 홍보, 당일 운영까지 해야 할 일이 산더미입니다. 축제까지 남은 시간은 2주.

    문제 B: 수학여행 계획

    학급 자치 시간에 수학여행 자유시간 계획을 세워야 합니다. 가고 싶은 곳 조사, 예산 계산, 이동 경로 짜기, 조 편성, 비상 연락망까지 준비해야 합니다. 발표까지 남은 시간은 3일.

    문제 C: 동아리 프로젝트

    동아리에서 교내 캠페인 프로젝트를 진행합니다. 주제 선정, 자료 조사, 포스터 제작, 발표 준비, 캠페인 실행까지 모든 것을 동아리원들이 나눠서 해야 합니다. 완료 기한은 한 달.

    개인 탐색¶

    아래 질문에 답해 보세요. 노트에 직접 적어보는 것을 권합니다.

    질문 1: 각 문제를 분해해 보세요

    2회차에서 배운 분해를 떠올리면서, 각 문제의 하위 문제를 3~4개씩 적어보세요. 완벽하지 않아도 됩니다. 대략적으로 적어보는 것이 중요해요.

    질문 2: 세 문제의 분해 결과를 비교해 보세요

    세 문제의 분해 결과를 나란히 놓고 보세요. 공통점이 보이나요? 보인다면 무엇인가요?

    비교하며 생각하기¶

    세 문제를 분해한 결과를 옆에 나란히 놓고, 아래 관점에서 비교해 보세요.

    • "문제 A의 '메뉴 선정'과 문제 B의 '가고 싶은 곳 조사'와 문제 C의 '주제 선정'은 혹시 같은 종류의 일 아닌가요?"
    • "세 문제 모두에서 사람들을 나누는 일이 들어있지 않나요?"
    • "세 문제 모두 마감이 있다는 공통점은 어떤가요?"
    이 탐색에서 발견하게 될 것

    세 문제 모두 "목표 설정 → 자원/정보 파악 → 역할 분담 → 일정 관리 → 실행"이라는 공통 구조를 가지고 있습니다. 겉모습(축제/여행/캠페인)은 다르지만, 뼈대(구조)는 놀랍도록 비슷합니다. 하나의 문제에서 배운 접근법이 다른 문제에도 적용될 수 있다는 뜻이에요.

    📌 핵심 개념 — 패턴 인식과 추상화¶

    방금 여러분이 발견한 것, 그러니까 "서로 다른 문제인데 구조가 비슷하다"는 것 — 이것을 Computational Thinking에서는 패턴 인식(Pattern Recognition)이라고 부릅니다. 그리고 그 공통 구조에서 핵심만 뽑아내는 것을 추상화(Abstraction)라고 합니다.

    패턴 인식 (Pattern Recognition)¶

    서로 다른 문제나 상황에서 반복되는 공통 구조, 규칙, 경향을 발견하는 것

    음악을 생각해 봅시다. 좋아하는 노래를 여러 곡 들어보면, "이 가수는 항상 후렴 전에 한 박자 쉬네" 같은 패턴이 보이기 시작합니다. 드라마도 마찬가지죠. 몇 편 보다 보면 "주인공이 위기에 빠졌다가 마지막에 역전하는 구조"가 반복된다는 걸 알게 됩니다.

    이렇게 반복되는 구조를 의식적으로 찾아내는 것이 패턴 인식입니다.

    추상화 (Abstraction)¶

    문제에서 핵심적인 요소만 남기고 불필요한 세부사항을 걸러내는 것

    지하철 노선도를 생각해 보세요. 실제 서울 지도 위에 지하철 경로를 그리면 굽이굽이 복잡합니다. 하지만 노선도에서는 "어느 역에서 어느 역으로 갈 수 있는가"라는 핵심만 남기고, 실제 거리나 곡선 같은 세부사항은 제거합니다. 그래서 한눈에 파악이 되죠.

    이것이 중요한 것과 중요하지 않은 것을 구별하는 기술, 추상화입니다.

    학교생활에서의 패턴 인식¶

    상황 발견할 수 있는 패턴
    시험 준비를 여러 번 함 "개념 정리 → 문제 풀기 → 오답 분석"이 반복됨
    조별 과제를 여러 번 함 "주제 정하기 → 역할 나누기 → 각자 작업 → 합치기"가 반복됨
    발표를 여러 번 함 "주제 선정 → 자료 수집 → 슬라이드 제작 → 연습 → 발표"가 반복됨
    여러 과목의 서술형 문제를 풀어봄 "주장 → 근거 → 사례 → 결론" 구조가 반복됨

    패턴을 한 번 발견하면 강력한 무기가 됩니다. 새로운 문제를 만나도 "아, 이건 전에 본 구조와 비슷하네"라고 인식하는 순간, 해결 방법이 훨씬 빨리 보이기 때문입니다.

    학교생활에서의 추상화¶

    원래 상태 추상화 결과 추상화가 하는 일
    소설 한 편 (200페이지) 핵심 한 줄 요약 줄거리, 묘사, 대화 중 주제만 추출
    수학 문제 100개 공식 하나 (예: a² + b² = c²) 개별 숫자를 변수로, 구체적 상황을 일반 법칙으로
    보드게임의 플레이 경험 게임 규칙서 (A4 1장) 모든 경우의 수 중 핵심 규칙만 추출
    한 학기 수업 내용 시험 범위 요약 정리 노트 예시, 반복, 부연 설명을 제거하고 핵심 개념만

    추상화를 잘하는 사람은, 정보의 바다에서 허우적대지 않습니다. 필요한 것만 건져 올리니까요.

    패턴 인식 + 추상화 = 일반화의 힘¶

    패턴 인식과 추상화는 함께 쓰일 때 진짜 위력을 발휘합니다. 이 흐름을 살펴보세요.

    flowchart TD A["여러 문제를 경험한다"] --> B B["패턴 인식: 이 문제들에 공통 구조가 있다!"] --> C C["추상화: 공통 구조에서 핵심만 뽑으면 이렇다!"] --> D D["일반화된 프레임워크 → 새로운 문제에도 적용 가능!"]

    방금 탐색에서 한 것을 되짚어 봅시다¶

    단계 여러분이 한 것
    분해 (2회차) 각 문제를 하위 문제로 쪼갬
    패턴 인식 (오늘) 세 문제의 분해 결과에서 비슷한 구조를 발견함
    추상화 (오늘) 그 비슷한 구조에서 핵심만 뽑아 "목표 → 자원 → 역할 → 일정 → 실행"으로 정리함

    축제, 여행, 캠페인이라는 세부사항을 걸러내고 나면, 남는 것은 "기획 프로젝트의 공통 프레임워크"입니다. 이제 여러분은 체육대회 기획이 주어져도, 학급 신문 제작이 주어져도, 이 프레임워크를 꺼내 쓸 수 있습니다.

    패턴 인식과 추상화, 헷갈릴 때

    • 패턴 인식 = "같은 점 찾기"
    • 추상화 = "핵심만 남기기"

    같은 점을 먼저 찾고, 그중에서 진짜 중요한 것만 추리는 것이 추상화예요. 순서가 있습니다: 패턴 인식이 먼저, 추상화가 그다음입니다.

    🛠️ 실습 — 패턴 발견 + 추상화 워크시트¶

    이제 직접 해볼 시간입니다. 오늘 실습은 두 단계로 진행됩니다.

    • 1단계: 세 가지 문제의 분해 결과를 나란히 놓고, 공통 패턴을 찾아 추출합니다.
    • 2단계: 추출한 패턴을 일반화하여, 어떤 문제에도 적용할 수 있는 프레임워크를 만듭니다.

    중요한 마음가짐

    "정답을 맞히는 것"이 목적이 아닙니다. "왜 이것이 핵심이라고 생각했는가"를 설명할 수 있으면 충분합니다.

    [1단계] 세 문제를 분해하고 나란히 놓기¶

    워크시트 1/2 — 분해 비교표

    아래 표의 각 칸에 해당 문제의 하위 문제를 적어보세요. 앞의 탐색 활동에서 적은 것을 활용해도 좋습니다.

    순서 A. 학교 축제 기획 B. 수학여행 계획 C. 동아리 프로젝트
    첫 번째로 해야 할 일
    두 번째로 해야 할 일
    세 번째로 해야 할 일
    네 번째로 해야 할 일
    다섯 번째로 해야 할 일

    1단계 팁

    분해에 너무 시간을 쏟지 않아도 됩니다. 2회차에서 배운 것을 떠올리면서 빠르게 적어보세요. 완벽하지 않아도 괜찮아요. 각 문제의 하위 문제 개수가 달라도 됩니다.

    [2단계] 패턴 찾기 — "공통점이 보이나요?"¶

    워크시트 1/2 — 공통 패턴 발견

    위 표에서 같은 줄에 있는 항목들을 가로로 비교하세요. 비슷한 성격의 항목끼리 같은 색으로 표시해 보세요.

    발견한 공통 패턴을 아래에 적어보세요.

    공통 패턴 A에서는 B에서는 C에서는
    공통 패턴 1: __
    공통 패턴 2: __
    공통 패턴 3: __
    공통 패턴 4: __
    공통 패턴 5: __
    '다 다른데요?'라고 느껴진다면

    "메뉴를 정하는 것"과 "장소를 정하는 것", "주제를 정하는 것"을 비교해 보세요. 이것들의 공통점은 뭘까요? 모두 "무엇을 할지 결정하는" 일 아닌가요? 이런 시각으로 다시 살펴보세요.

    [3단계] 추상화 — "핵심만 남기기"¶

    워크시트 2/2 — 추상화

    2단계에서 찾은 공통 패턴에서 "축제", "여행", "캠페인"이라는 구체적인 단어를 빼고, 어디에나 적용되는 일반적인 표현으로 바꿔 보세요.

    예시

    • 구체적 패턴: "메뉴 선정 / 장소 조사 / 주제 선정"
    • 추상화 결과: "핵심 대상 결정하기"

    나의 추상화 결과:

    단계 추상화 결과 구체적으로는
    단계 1
    단계 2
    단계 3
    단계 4
    단계 5
    추상화가 어렵게 느껴진다면

    구체적인 단어를 하나씩 빼보세요. "축제 메뉴 선정"에서 "축제"를 빼면? "메뉴 선정". 거기서 "메뉴"를 빼면? "대상 결정". 이런 식으로 점점 일반적인 표현으로 바꿔나가면 됩니다. 또는 이렇게 생각해 보세요: "만약 외국인에게 이 세 문제를 한꺼번에 설명해야 한다면, '축제', '여행', '캠페인'이라는 단어 없이 어떻게 설명할 수 있을까?"

    [4단계] 일반화된 프레임워크 완성¶

    나의 프레임워크

    3단계의 결과를 하나의 프레임워크로 정리합니다. 이 프레임워크는 축제, 여행, 캠페인뿐 아니라 어떤 기획 문제에도 적용할 수 있어야 합니다.

    나의 프레임워크 이름: "____ 프레임워크"

    [ 단계 1 ] → [ 단계 2 ] → [ 단계 3 ] → [ 단계 4 ] → [ 단계 5 ]

    [5단계] 검증 — "정말 다른 문제에도 통하는가?"¶

    위에서 만든 프레임워크를 전혀 새로운 문제에 적용해 봅시다.

    새로운 문제에 적용하기

    아래에서 하나를 고르거나, 직접 정하세요:

    • 체육대회 준비
    • 학급 신문 만들기
    • 생일 파티 기획
    • 직접 쓰기: ____

    선택한 문제: ____

    프레임워크 적용 결과:

    프레임워크 단계 이 문제에서는
    단계 1 ( )
    단계 2 ( )
    단계 3 ( )
    단계 4 ( )
    단계 5 ( )

    적용이 잘 안 된다면?

    프레임워크가 새 문제에 적용되지 않으면, 그것도 중요한 발견입니다. "적용이 안 된다면, 프레임워크를 수정하면 됩니다." 그게 바로 "검증"의 목적이에요. 프레임워크를 완벽하게 만드는 것보다, 수정할 줄 아는 것이 더 중요합니다.

    [6단계] 자기 검증 체크리스트¶

    실습이 끝나면 스스로 점검해 보세요.

    • 세 문제에서 공통 패턴을 3개 이상 찾았는가?
    • 추상화할 때 특정 문제에만 해당하는 단어를 제거했는가?
    • 프레임워크가 새로운 문제에도 적용되는가?
    • "왜 이것이 핵심인가"를 설명할 수 있는가?
    • 빠뜨린 단계는 없는가?

    🔄 공유와 검증 — 서로의 프레임워크를 비교해 봅시다¶

    혼자 만든 프레임워크를 다른 사람의 것과 비교하면, 새로운 관점을 얻을 수 있습니다. 친구나 모둠원과 워크시트를 교환하고 아래 기준으로 검토해 보세요.

    패턴 발견 피드백 체크리스트

    패턴 인식 검증

    • 세 문제에서 공통 패턴을 3개 이상 찾았는가?
    • 찾은 패턴이 "진짜 공통점"인가? (한 문제에만 해당하는 것은 아닌가?)
    • 패턴 연결이 자연스러운가? (A의 "메뉴 선정"과 B의 "예산 계산"을 같은 패턴이라고 한 것은 아닌가?)

    추상화 검증

    • 추상화 결과에서 "축제", "여행", "캠페인" 같은 특정 단어가 제거되었는가?
    • 추상화 결과가 너무 모호하지는 않은가? (예: "일하기"처럼 아무 의미 없는 수준이 아닌가?)
    • 추상화 결과만 보고도 "아, 이런 뜻이구나"를 이해할 수 있는가?

    프레임워크 검증

    • 새로운 문제에 적용한 결과가 납득이 되는가?
    • 프레임워크의 단계 순서가 논리적인가?

    비교하면서 생각해 볼 것¶

    피드백을 주고받은 후, 다음 질문을 스스로에게 던져 보세요.

    • "상대방이 지적한 점 중 수긍이 가는 것은?"
    • "내가 놓친 패턴이 있었는가?"
    • "추상화 수준이 적절했는가, 아니면 너무 구체적이거나 너무 모호했는가?"

    서로 다른 사람이 서로 다른 문제를 보면서도 비슷한 프레임워크를 만들어냈다면 — 그것 자체가 패턴의 존재를 증명하는 것입니다.

    같은 문제를 보면서도 서로 다른 프레임워크를 만들었다면 — 그것은 추상화에 "하나의 정답"이 없다는 것을 보여줍니다.

    중요한 것은 "왜 그렇게 추상화했는가"를 설명할 수 있느냐입니다.

    🔍 참고: 예시 답안¶

    아래는 여러분이 도달할 수 있는 추상화 결과의 한 가지 예시입니다. 정답이 아니라 참고용이에요. 여러분의 답이 이것과 다르더라도 전혀 문제없습니다.

    공통 패턴 A (축제) B (여행) C (캠페인) 추상화 결과
    뭘 할지 정하기 메뉴 선정 장소 조사 주제 선정 목표/대상 결정
    뭐가 필요한지 파악 재료/예산 예산/교통 자료/재료 자원 파악
    누가 뭘 할지 나누기 역할 분담 조 편성 역할 분담 역할 배분
    언제까지 할지 정하기 2주 계획 3일 계획 한 달 계획 일정 수립
    실제로 하기 당일 운영 자유시간 캠페인 실행 실행 및 운영

    일반화된 프레임워크:

    목표 결정 → 자원 파악 → 역할 배분 → 일정 수립 → 실행 및 운영

    보너스 활동: 다른 영역의 패턴 찾기

    시간 여유가 있다면 아래 세 활동에서도 공통 패턴을 찾아보세요.

    • (가) 시험 공부: 개념 정리 → 문제 풀기 → 오답 분석 → 복습
    • (나) 운동 훈련: 기초 동작 → 실전 연습 → 영상 분석 → 반복
    • (다) 요리 배우기: 레시피 읽기 → 직접 만들기 → 맛 평가 → 개선

    공통 패턴이 보이나요? 힌트: "이론 → 실행 → 피드백 → 반복"이라는 구조가 숨어있습니다.

    📖 정리 — 오늘의 핵심¶

    핵심 한 줄¶

    "서로 다른 문제 속에서 공통 구조를 찾고(패턴 인식), 핵심만 남기면(추상화), 어떤 새로운 문제에도 적용할 수 있는 프레임워크가 만들어진다."

    오늘의 키워드¶

    키워드 의미
    패턴 인식 (Pattern Recognition) 서로 다른 문제에서 반복되는 공통 구조를 발견하는 것
    추상화 (Abstraction) 핵심만 남기고 불필요한 세부사항을 걸러내는 것
    일반화 (Generalization) 추상화된 구조를 다른 문제에도 적용 가능하게 만드는 것

    CT 요소 연결 — 지금까지의 여정¶

    flowchart TD A["1회차: CT 소개 + 첫 분해 경험"] --> B B["2회차: 분해 Decomposition + MECE<br>'큰 문제를 작은 문제로 나눈다'"] --> C C["3회차: 패턴 인식 + 추상화 ← 오늘 여기!<br>'공통 구조를 찾고, 핵심만 남긴다'"] --> D D["4회차: 알고리즘 설계 (다음 시간!)<br>'해결 절차를 단계별로 만든다'"]

    핵심 메시지 세 가지¶

    1. 패턴은 "발견"하는 것이지 "외우는" 것이 아닙니다 — 공식을 외우는 것이 아니라, 공식이 나오게 된 구조를 이해하는 것이 오늘의 목적이었습니다.

    2. 추상화에는 정답이 없습니다 — 같은 정보에서 다른 핵심을 추출할 수 있고, 그것이 자연스럽습니다. 중요한 것은 "왜 이것이 핵심인가"를 설명할 수 있느냐입니다.

    3. 패턴 + 추상화 = 전이(Transfer)의 기초 — 한 분야에서 배운 것을 다른 분야에 적용할 수 있게 해주는 것이 패턴 인식과 추상화입니다. 이것이 앞으로의 모든 학습으로 이어지는 핵심 능력입니다.

    선택 과제¶

    이번 주에 일상에서 패턴을 한 번 찾아보세요. "이 일과 저 일의 구조가 비슷하네!"라고 느끼는 순간이 있다면, 메모해 두세요. 어떤 패턴이든 좋습니다.
