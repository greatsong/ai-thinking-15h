# 커리큘럼 생성 Harness (v2 — 일반화)

> 이 문서는 커리큘럼 "자체"가 아니라, 커리큘럼을 "만드는 기준"이다.
> v2 개선: 특정 인물/에피소드 종속에서 벗어나 교육학적 원리 기반으로 일반화.

---

## 1. 목적 (Soul)

이 커리큘럼은 학습자가 **AI 시대에 필요한 세 가지 역량**을 계층적으로 습득하도록 설계된다:

```
Layer 1: 구조적 사고력        → "어떻게 생각할 것인가"  (Computational Thinking)
Layer 2: AI 협업 설계력       → "어떻게 시킬 것인가"   (메타인지 + 시스템 설계)
Layer 3: 분야 융합 적용력     → "어디에 쓸 것인가"     (전이 학습 + 가치 창출)
```

## 2. 이론적 기반

이 커리큘럼은 다음 교육 이론과 연결된다:

| 계층 | 교육학적 근거 | 핵심 개념 |
|------|-------------|-----------|
| Layer 1 | Computational Thinking (Wing, 2006) | 분해, 패턴 인식, 추상화, 알고리즘 설계 |
| Layer 2 | 메타인지(Flavell), Scaffolding(Vygotsky) | 사고에 대한 사고, 구조화된 지원 |
| Layer 3 | 전이 학습(Transfer Learning), 융합 교육(STEAM) | 한 맥락의 학습을 다른 맥락에 적용 |
| 평가 | Bloom's Taxonomy (개정판) | 기억 → 이해 → 적용 → 분석 → 평가 → 창조 |

## 3. 철학 (절대 원칙)

### 지켜야 할 것

1. **탐색 우선 원칙**: 모든 모듈은 "질문"으로 시작한다 (답을 먼저 가르치지 않는다)
2. **설계 중심 실습**: 결과물을 직접 만드는 것이 아니라, "결과물을 만드는 구조"를 설계한다
3. **과정 중심 평가**: 결과물의 완성도가 아니라 사고의 구조화 과정을 평가한다
4. **도구 독립성**: 특정 AI 도구에 종속되지 않는 보편적 원리를 가르친다
5. **다양한 사례 활용**: 교육, 비즈니스, 창작, 의료, 일상 등 폭넓은 맥락에서 사례를 든다

### 피해야 할 것

- 특정 도구의 사용법 나열 (도구는 바뀌므로)
- 특정 인물이나 사례에 과도하게 의존 (보편성 저해)
- "이렇게 하면 됩니다" 식의 정답 제시 (학습자의 탐색 기회 박탈)
- 결과물 중심 평가 ("잘 만들었느냐"가 아니라 "잘 구조화했느냐")
- AI 없이는 성립하지 않는 실습 (Layer 1은 AI 없이도 가능해야 함)

## 4. 핵심 개념 용어 정의

커리큘럼 전체에서 일관되게 사용하는 용어:

| 용어 | 정의 | 예시 |
|------|------|------|
| **구조적 사고** | 문제를 정의하고, 분해하고, 패턴을 찾아 해결 구조를 세우는 능력 | "학교 축제 기획"을 10개 하위 과제로 분해 |
| **AI 협업 설계서** | AI가 효과적으로 작동하도록 목적, 맥락, 규칙, 품질 기준을 명시한 문서 | 프로젝트의 목적, 구조, 진행 추적, 협업 규칙을 담은 문서 |
| **설계 수준** | AI 활용의 성숙도를 3단계로 구분 | 수준 1(직접 요청) → 수준 2(패턴 기반) → 수준 3(시스템 설계) |
| **가치 창출 지점 분석** | 자기 분야에서 AI가 실질적 가치를 만들 수 있는 지점을 찾는 분석법 | 반복성, 구조화 가능성, 전문성 갭을 기준으로 적용점 탐색 |
| **생성 장치** | 1회성 결과물이 아니라, 결과물을 반복적으로 만들어내는 구조/시스템 | 이메일 하나를 쓰는 것 vs 이메일을 자동 생성하는 기준을 만드는 것 |

## 5. 모듈 설계 템플릿

> 모든 모듈은 이 템플릿을 따른다. 이것이 "생성 장치"의 핵심이다.

```
## 모듈 N: [모듈 제목]

### 소속 계층
Layer 1 / Layer 2 / Layer 3

### 학습 목표
이 모듈을 마치면 학습자는 ___할 수 있다.
(Bloom's Taxonomy 기준: 어떤 수준의 인지 활동인지 명시)

### 도입 (10분) — "왜 이것이 필요한가?"
- 실제 사례 또는 비유로 시작 (다양한 분야에서 선택)
- "이 능력이 없으면 어떤 문제가 생기는가?"로 필요성 체감
- 학습자의 경험과 연결

### 탐색 (15분) — "먼저 생각해보자"
- 학습자에게 열린 질문을 던진다 (답을 가르치지 않는다)
- 개인 탐색 → 모둠 토론 순서
- 탐색 질문은 2~3개, 점차 구체적으로

### 핵심 개념 (15분) — "이런 관점이 있다"
- 탐색 결과를 바탕으로 핵심 프레임워크 정리
- 학습자가 스스로 도달한 생각과 교육학적 개념을 연결
- 실제 사례 2~3개로 개념 보강 (교육, 비즈니스, 일상 등 다양하게)

### 실습 (30분) — "구조를 설계해보자"
- 직접 결과물을 만드는 것이 아님
- "이 문제를 풀기 위한 구조/기준/규칙"을 설계
- 워크시트에 따라 단계별 진행
- 결과: 학습자가 작성한 설계 문서

### 공유와 검증 (15분) — "서로의 설계를 검증하자"
- 모둠 간 설계 문서 교환
- 검증 체크리스트를 기반으로 구조적 피드백
- "이 설계대로 실행하면 원하는 결과가 나올까?"
- 개선점 도출 및 반영

### 정리 (5분) — "오늘의 핵심"
- 핵심 한 줄 요약
- 다음 모듈과의 연결 안내
- 선택적 심화 과제 안내

---
총 90분 기준 (조절 가능)
```

## 6. 계층별 모듈 배치 규칙

```
[Layer 1: 구조적 사고력] — 전체의 30%
  → Computational Thinking의 4요소: 분해, 패턴 인식, 추상화, 알고리즘 설계
  → AI 없이도 할 수 있는 활동 반드시 포함
  → 일상, 학교, 직장의 실제 문제를 재료로 사용
  → Bloom's: 분석(Analyze) 수준까지

[Layer 2: AI 협업 설계력] — 전체의 40%
  → AI 활용 3단계(직접 요청 → 패턴 기반 → 시스템 설계) 체험
  → AI 협업 설계서 작성 실습
  → 탐색적 대화 설계, 지식 체계 구축, 워크플로우 설계
  → 다양한 직군(교사, 기획자, 연구자, 관리자 등)의 사례 활용
  → Bloom's: 평가(Evaluate) 수준까지

[Layer 3: 분야 융합 적용력] — 전체의 30%
  → 자기 도메인에서 AI 적용 가치가 있는 지점 분석
  → 가치 창출 지점 분석 프레임워크 (반복성, 구조화 가능성, 전문성 갭, 시간 절감)
  → 최종 산출물: 도메인별 AI 협업 설계서 + 실행 결과
  → Bloom's: 창조(Create) 수준까지
```

## 7. 평가 기준 Harness

> 결과물이 아니라 과정을 평가한다. Bloom's Taxonomy와 연계.

```
[평가 항목]

1. 구조적 사고력 (Layer 1) — Bloom's: 분석
   - 문제를 명확하게 정의했는가?
   - MECE(상호 배타적, 전체 포괄적)하게 분해했는가?
   - 패턴을 인식하고 추상화했는가?

2. AI 협업 설계력 (Layer 2) — Bloom's: 평가
   - 설계서에 목적, 맥락, 규칙, 품질 기준이 명시되어 있는가?
   - 수준 3(시스템 설계) 수준에 도달했는가?
   - 이 설계서대로 실행하면 일관된 결과가 나올 수 있는가?
   - 탐색적 대화 설계가 적절한가?

3. 분야 융합 적용력 (Layer 3) — Bloom's: 창조
   - 자기 분야의 맥락이 충분히 반영되었는가?
   - AI 적용의 실질적 가치를 식별했는가?
   - 실제로 작동하는가? (또는 작동할 수 있는 논리적 근거가 있는가?)

4. 협업 과정 (공통)
   - AI와의 대화에서 탐색적 접근을 사용했는가?
   - 피드백을 반영하여 설계를 개선했는가?
   - 다른 학습자의 설계에 건설적 피드백을 제공했는가?
```

## 8. 사례 활용 가이드

> 특정 인물이나 에피소드에 의존하지 않고, 다양한 맥락에서 사례를 선택한다.

### 사례 선택 기준
1. **다양성**: 교육, 비즈니스, 의료, 창작, 공공, 일상 등 최소 3개 분야
2. **접근성**: 학습자가 공감할 수 있는 일상적 상황 우선
3. **보편성**: 특정 기업/인물에 종속되지 않는 원리 중심
4. **시의성**: 최신 AI 활용 사례를 포함하되, 원리는 보편적으로

### 분야별 사례 예시 풀

| 분야 | 구조적 사고 사례 | AI 협업 설계 사례 | 분야 융합 사례 |
|------|----------------|------------------|--------------|
| 교육 | 수업 설계를 하위 요소로 분해 | 학생 피드백 자동 생성 설계서 | 교과별 AI 보조 학습 시스템 |
| 비즈니스 | 고객 불만 원인 구조화 | 보고서 자동 작성 시스템 설계 | 마케팅+AI 캠페인 최적화 |
| 의료 | 증상 → 진단 흐름 구조화 | 의료 기록 요약 설계서 | 의료+AI 환자 상담 보조 |
| 창작 | 소설 플롯 구조 분해 | 캐릭터 설정 생성 시스템 설계 | 문학+AI 스토리텔링 |
| 일상 | 여행 계획 하위 과제 분해 | 가계부 자동 분류 설계서 | 생활+AI 루틴 최적화 |
| 공공 | 정책 효과 분석 구조화 | 민원 응답 시스템 설계서 | 행정+AI 의사결정 지원 |

## 9. 확장 규칙

### 기간별 조절
- **4주 과정**: Layer 1(1주) + Layer 2(2주) + Layer 3(1주) — 핵심 체험
- **8주 과정**: 각 Layer에 2~3개 모듈 — 표준 심화
- **16주 과정**: 각 Layer에 4~6개 모듈 + 종합 프로젝트 — 정규 과정

### 대상별 강조점
- **학생(초·중등)**: Layer 1 비중 높게, 일상과 학교 맥락의 사례 중심
- **교사**: Layer 2 비중 높게, 교과 연계 AI 협업 설계 실습
- **직장인**: Layer 3 비중 높게, 즉시 업무 적용 가능한 설계
- **비전문가**: Layer 2부터 시작 가능 (간단한 설계서 작성으로 입문)

### 새 모듈 추가 시
1. 이 Harness의 모듈 설계 템플릿을 따른다
2. 소속 계층(Layer 1/2/3)을 명시한다
3. Bloom's Taxonomy 수준을 명시한다
4. 사례 활용 가이드에 따라 다양한 분야의 사례를 포함한다
5. 평가 기준과 정합성을 확인한다
