# 6회차: AI 협업 설계서 만들기

> **과정**: AI 시대의 구조적 사고 -- 생각하는 힘 키우기
> **Layer**: Layer 2 -- AI 협업 설계력
> **회차**: 6/10 (90분)
> **대상**: 고등학교 1~2학년

---

## 학습 목표

이번 회차를 마치면 다음을 할 수 있습니다.

1. AI 협업 설계서의 3요소(목적-규칙-맥락)를 이해하고 각각의 역할을 설명할 수 있다
2. 자기 업무(학교 과제, 동아리 활동 등) 하나에 대한 AI 협업 설계서를 작성할 수 있다
3. 작성한 설계서의 수준을 자기 검증(메타인지 점검)할 수 있다

## 도입 (10분) -- "왜 이것이 필요한가?"

### 5회차 복습: 3수준 빠르게 되짚기

지난 시간에 우리는 AI에게 시키는 방법에 '수준'이 있다는 것을 발견했습니다.

```
수준 1: "숙제 도와줘"             --> 물고기를 받는 것
수준 2: "내 패턴대로 써줘"         --> 낚시를 배우는 것
수준 3: "이 기준으로 시스템 만들어" --> 양식장을 설계하는 것
```

> **진행자 발문**: "지난 시간에 수준 3으로 바꾸는 연습을 했는데, 솔직히 어땠나요? '수준 3이 좋다는 건 알겠는데, 어떻게 만드는 건데?'라는 생각이 들지 않았나요?"

대부분의 학생이 고개를 끄덕일 것입니다. 그것이 자연스러운 반응입니다.

### 오늘의 핵심 질문

> "수준 3이 좋다는 건 알겠다. 그런데... **어떻게** 만드는 건데?"

5회차에서 우리는 '수준'을 알았고, 오늘은 그 수준 3을 실제로 만드는 '방법'을 배웁니다. 바로 **AI 협업 설계서**입니다.

### 비유: 요리 레시피

여러분이 누군가에게 요리를 부탁한다고 상상해 봅시다.

| 방식 | 말하는 것 | 결과 |
|------|----------|------|
| 수준 1 | "맛있는 거 해줘" | 뭐가 나올지 모름 |
| 수준 2 | "김치찌개 해줘, 좀 매콤하게" | 대충 비슷하지만 내 입맛과 다를 수 있음 |
| 수준 3 | 레시피 전달: 재료, 양, 순서, 불 세기, 간 기준 | 누가 해도 비슷한 맛이 남 |

여기서 '레시피'에 해당하는 것이 바로 오늘 만들 **AI 협업 설계서**입니다. AI에게 건네는 레시피라고 생각하면 됩니다.

> **진행자 팁**: "레시피가 있으면 요리 초보도 따라 할 수 있죠? AI 협업 설계서도 마찬가지입니다. 잘 쓰인 설계서가 있으면, AI가 여러분이 원하는 방향으로 일관되게 결과를 만들어 줄 수 있습니다." 이 비유는 이후 실습에서도 계속 활용되므로, 학생들이 기억할 수 있도록 강조합니다.

## 탐색 (15분) -- "먼저 생각해보자"

### 개인 탐색 (5분): "AI에게 꼭 알려줘야 하는 정보는?"

다음 상황을 생각해 봅시다.

> 여러분이 친한 친구에게 '내 대신 동아리 활동 보고서를 써달라'고 부탁한다면, 그 친구에게 **최소한** 어떤 정보를 알려줘야 할까요?

종이나 노트에 떠오르는 것을 자유롭게 적어 보세요. 정답은 없습니다. 최소 5개를 목표로 해 봅시다.

```
+-----------------------------------------------------+
|    AI에게 꼭 알려줘야 하는 정보                        |
+-----------------------------------------------------+
|                                                     |
| 1. ____________________________________________     |
|                                                     |
| 2. ____________________________________________     |
|                                                     |
| 3. ____________________________________________     |
|                                                     |
| 4. ____________________________________________     |
|                                                     |
| 5. ____________________________________________     |
|                                                     |
| 6. ____________________________________________     |
|                                                     |
| 7. ____________________________________________     |
|                                                     |
+-----------------------------------------------------+
```

> **진행자 팁**: 학생들이 막막해하면 이렇게 보조 질문을 던집니다. "그 친구가 '뭘 써야 하는데?'라고 물으면 뭐라고 답할 건가요?" / "친구가 '어떤 식으로 써야 해?'라고 물으면요?" / "친구가 '이 동아리에 대해 나는 아무것도 모르는데?'라고 하면요?" 이 세 질문이 자연스럽게 목적-규칙-맥락으로 이어집니다.

### 모둠 브레인스토밍 (7분)

4인 모둠으로 각자 적은 항목을 공유합니다. 그리고 모둠별로 하나의 리스트로 합칩니다.

**활동 방법**:

1. 돌아가며 한 명씩 자기가 적은 항목을 읽는다
2. 다른 사람의 것과 비슷한 항목은 묶는다
3. 최종적으로 모둠 리스트를 만든다

> **진행자 팁**: 이 단계에서 "맞다/틀리다"를 판단하지 않습니다. "좋은 지적이에요!", "그것도 중요하겠네요"처럼 모든 의견을 수용합니다.

### 전체 공유 (3분)

각 모둠이 "가장 중요하다고 생각하는 항목 3가지"를 발표합니다.

진행자는 칠판이나 화면에 키워드를 정리합니다. 아마 이런 것들이 나올 것입니다:

- "뭘 해야 하는지" (목적)
- "어떤 형식으로" / "분량은" / "하면 안 되는 것" (규칙)
- "누가 읽는 건지" / "어떤 동아리인지" / "지금까지 한 활동" (맥락)

> **진행자 발문**: "여러분이 찾은 것들을 잘 보세요. 크게 세 묶음으로 나뉘지 않나요? '왜 하는지', '어떻게 해야 하는지', '뭘 알아야 하는지'. 이것을 정리하면 바로 오늘의 핵심 개념이 됩니다."

## 핵심 개념 (15분) -- "이런 관점이 있다"

### 탐색 결과와의 연결

> "여러분이 탐색 시간에 직접 찾아낸 것 -- '뭘 해야 하는지', '어떻게 해야 하는지', '뭘 알아야 하는지' -- 이것이 바로 AI 협업 설계의 3요소입니다. 여러분은 이미 핵심을 발견한 것입니다."

### AI 협업 설계서의 3요소

```
+---------------------------------------------------+
|              AI 협업 설계서의 3요소                   |
+---------------------------------------------------+
|                                                   |
|   [1] 목적 (Purpose)                              |
|       "이 시스템은 왜 존재하는가?"                   |
|       -- 무엇을 달성하려고 하는가                    |
|       -- 성공하면 어떤 모습인가                      |
|                                                   |
|              |                                     |
|              v                                     |
|                                                   |
|   [2] 규칙 (Rules)                                |
|       "어떤 기준을 따라야 하는가?"                   |
|       -- 반드시 지켜야 할 것 (Do)                   |
|       -- 절대 하면 안 되는 것 (Don't)               |
|                                                   |
|              |                                     |
|              v                                     |
|                                                   |
|   [3] 맥락 (Context)                              |
|       "판단에 필요한 배경 정보는?"                   |
|       -- 대상/상황/조건                             |
|       -- 참고 자료                                 |
|       -- 성공의 기준                                |
|                                                   |
+---------------------------------------------------+
```

각 요소가 왜 필요한지, 하나씩 살펴봅시다.

### 요소 1: 목적 (Purpose)

**핵심 질문**: "이 시스템은 왜 존재하는가?"

목적이 빠지면 AI는 '방향'을 모릅니다. 목적이 없는 설계서는 목적지 없는 내비게이션과 같습니다.

**좋은 목적의 조건**: 한 문장으로 말할 수 있어야 합니다.

| 모호한 목적 | 명확한 목적 |
|------------|------------|
| "공부를 잘 하고 싶다" | "다음 중간고사 수학에서 80점 이상을 받기 위한 학습 계획을 세운다" |
| "발표를 잘 하고 싶다" | "10분 분량의 과학 탐구 발표 원고와 슬라이드 구성안을 만든다" |
| "동아리를 잘 운영하고 싶다" | "독서 동아리 월간 활동 보고서를 일관된 형식으로 작성한다" |

> **진행자 팁**: "모호한 목적"에서 "명확한 목적"으로 바꾸는 과정 자체가 사고의 구조화입니다. 학생들에게 "목적을 명확하게 쓰는 것 자체가 이미 절반은 해결한 것"이라고 강조합니다.

### 요소 2: 규칙 (Rules)

**핵심 질문**: "어떤 기준을 따라야 하는가?"

규칙에는 두 종류가 있습니다.

- **Do (지켜야 할 것)**: "반드시 이것을 포함해라"
- **Don't (피해야 할 것)**: "절대 이것은 하지 마라"

**왜 Don't가 중요할까요?**

Do만 있으면 AI는 원하는 것을 해주되, 원하지 않는 것도 함께 할 수 있습니다. Don't를 명시하면 '경계'가 생깁니다.

| 상황 | Do | Don't |
|------|-----|-------|
| 시험 공부 계획 수립 | 교과별 시간 배분 포함 / 취약 단원 우선 / 복습 주기 반영 | 하루 10시간 이상 계획 금지 / 한 과목에 편중 금지 |
| 독서 감상문 작성 | 핵심 주제 1가지 선택 / 자기 경험과 연결 / 인용 포함 | 줄거리 요약에 그치지 않기 / 인터넷 서평 복사 금지 |
| 발표 자료 준비 | 슬라이드 10장 이내 / 핵심 메시지 3개 이하 / 시각 자료 포함 | 글자만 가득한 슬라이드 금지 / 한 슬라이드에 주제 2개 이상 금지 |

> **진행자 팁**: "규칙이 구체적이어야 하는 이유"를 이렇게 설명합니다. "'좋게 써라'는 규칙이 될 수 없습니다. '좋게'가 뭔지 사람마다 다르니까요. '강점 2가지를 먼저 언급하고, 개선점 1가지를 뒤에 쓴다'라고 하면 누구든 따를 수 있겠죠?"

### 요소 3: 맥락 (Context)

**핵심 질문**: "판단에 필요한 배경 정보는?"

같은 '독서 감상문'이라도 맥락에 따라 완전히 다른 결과가 필요합니다.

```
같은 과제, 다른 맥락:

맥락 A: 국어 수행평가 / 고1 / 문학 작품 / 800자 이내 / 선생님 평가
맥락 B: 독서 동아리 발표 / 자유 선택 도서 / 5분 발표 / 또래 청중
맥락 C: 대학 입시 자소서 소재 / 인문 분야 도서 / 독서 경험 서술 / 입학사정관

--> 세 경우 모두 '독서 감상문'이지만, 필요한 결과물은 완전히 다릅니다.
```

맥락에 포함할 수 있는 정보:

- **대상/독자**: 누가 이것을 볼 것인가?
- **상황/조건**: 어떤 환경에서 사용되는가?
- **주기/빈도**: 한 번인가, 반복되는가?
- **참고 자료**: 기존에 있는 자료가 있는가?
- **성공 기준**: 잘 되었는지 어떻게 판단하는가?

### 3요소가 갖춰진 사례 vs 빠진 사례

학생 사례로 비교해 봅시다. "시험 공부 계획 세우기"를 AI에게 맡긴다고 할 때:

**3요소가 빠진 경우 (수준 1)**:
> "시험 공부 계획 세워줘"

**3요소가 갖춰진 경우 (수준 3)**:
> **목적**: "다음 주 수요일 중간고사(수학, 영어, 과학) 대비 5일간의 학습 계획을 세운다."
>
> **규칙 (Do)**: 하루 총 학습 시간은 4시간 이내 / 취약 과목(수학)에 40% 이상 배분 / 매일 전날 복습 30분 포함 / 과목 간 전환 시 10분 휴식
>
> **규칙 (Don't)**: 하루에 한 과목만 하지 않기 / 새벽 공부 계획 넣지 않기 / 이미 잘 아는 단원에 시간 과배정 금지
>
> **맥락**: 고1 / 수학은 이차함수 단원이 약함 / 영어는 독해 위주 / 과학은 화학1 반응식 / 평일 방과후 4시~10시 가용 / 주말은 오전만 가능 / 목표: 전 과목 평균 80점 이상

차이가 보이시나요? 두 번째 설계서를 받은 AI(또는 사람)는 **구체적이고 실행 가능한 계획**을 만들 수 있습니다.

### Vygotsky의 비계(Scaffolding): 설계서는 '양쪽 비계'

교육학에서 Vygotsky는 **비계(Scaffolding)**라는 개념을 제안했습니다. 학습자가 혼자서는 못하지만, 적절한 도움(비계)이 있으면 해낼 수 있는 영역이 있습니다. 이것을 **근접 발달 영역(ZPD, Zone of Proximal Development)**이라고 합니다.

AI 협업 설계서는 바로 이 비계입니다. 그런데 흥미로운 점이 있습니다.

```
                    설계서의 두 가지 역할

    나 (학습자)                              AI (협업 도구)
        |                                       |
        |     +-------------------------+       |
        |     |    AI 협업 설계서         |       |
        |     |  (목적-규칙-맥락)         |       |
        |     +-------------------------+       |
        |              |                        |
        v              v                        v
   내 생각을          설계서가             AI에게 주는
   구조화하는      연결 다리 역할           작업 지침
   비계                                    (비계)
```

설계서를 쓰는 과정 자체가 **내 사고를 정리하는 비계**이고, 완성된 설계서는 **AI에게 주는 비계**입니다. 즉, 설계서는 나와 AI 모두에게 비계 역할을 하는 '양쪽 비계'입니다.

> **진행자 팁**: "이 개념은 AI에만 해당하는 것이 아닙니다. 후배에게 업무를 인수인계할 때, 팀 프로젝트에서 역할을 분담할 때, 심지어 미래의 자신에게 메모를 남길 때도 같은 구조입니다. '목적-규칙-맥락'이라는 프레임워크는 모든 협업에 적용됩니다."

### 핵심 정리

```
+-----------------------------------------------------+
|              이번 단계의 핵심                          |
+-----------------------------------------------------+
|                                                     |
| "수준 3이 좋다"는 걸 아는 것 -> 5회차에서 했음         |
|                                                     |
| "수준 3을 어떻게 만드는가" -> 오늘의 핵심              |
|                                                     |
| 방법: 목적 + 규칙 + 맥락 = AI 협업 설계서             |
|                                                     |
| 설계서의 가치:                                       |
|   (1) 내 사고를 구조화하는 도구 (나를 위한 비계)       |
|   (2) AI에게 명확한 지침 (AI를 위한 비계)             |
|                                                     |
+-----------------------------------------------------+
```

## 실습 (30분) -- "구조를 설계해보자"

### 과제 안내

> "이제 여러분이 직접 AI 협업 설계서를 만들어 볼 시간입니다. 자기 학교생활이나 일상에서 **반복되는 일** 하나를 골라서, 그것에 대한 설계서를 작성해 봅시다."

**중요**: 이번 실습에서는 AI를 직접 사용하지 않습니다. 설계서를 '작성'하는 것 자체에 집중합니다. 잘 설계된 설계서가 있어야 AI를 제대로 활용할 수 있기 때문입니다.

### 반복 작업 선택 가이드

어떤 과제를 선택할지 고민되는 학생을 위한 안내입니다.

```
+-----------------------------------------------------+
|        반복 작업 선택 도우미                            |
+-----------------------------------------------------+
|                                                     |
| 다음 중 해당하는 것에 V 표시해 보세요.                  |
|                                                     |
| 학교 과제:                                           |
|   [ ] 독서 감상문 / 독후감 쓰기                       |
|   [ ] 과목별 시험 공부 계획 세우기                     |
|   [ ] 발표 자료(PPT) 만들기                          |
|   [ ] 수행평가 보고서 작성                            |
|   [ ] 서술형 답안 구조 잡기                           |
|                                                     |
| 동아리/학교 활동:                                     |
|   [ ] 동아리 활동 보고서 작성                          |
|   [ ] 학급 회의 안건 정리                             |
|   [ ] 축제/행사 기획안 작성                           |
|   [ ] 학교 신문/방송 원고 쓰기                        |
|                                                     |
| 일상/자기관리:                                       |
|   [ ] 주간 학습 계획 세우기                           |
|   [ ] 일기/학습 일지 쓰기                             |
|   [ ] 진로 탐색 자료 정리                             |
|                                                     |
| --> 이 중 가장 자주 하는 것, 또는 할 때마다             |
|     막막했던 것 하나를 선택하세요.                      |
|                                                     |
| 나의 선택: ____________________________________      |
|                                                     |
+-----------------------------------------------------+
```

> **진행자 팁**: "너무 큰 과제를 선택하면 설계서 작성이 어렵습니다. '모든 공부를 잘 하기'보다는 '수학 서술형 시험 대비 계획 세우기'처럼 범위를 좁히도록 안내합니다. 선택에서 막히는 학생에게는 '지난주에 가장 시간을 많이 쓴 일이 뭐예요?'라고 물어보면 대부분 떠올립니다."

### 워크시트: 나의 첫 AI 협업 설계서

다음 워크시트를 단계별로 작성합니다.

```
+===========================================================+
|                                                           |
|           나의 첫 AI 협업 설계서                             |
|                                                           |
+===========================================================+
|                                                           |
| 이름: ________________    날짜: ________________           |
|                                                           |
| 선택한 반복 작업: _______________________________________   |
|                                                           |
+===========================================================+
|                                                           |
| [1] 목적 (Purpose) -- "왜 이것을 하는가?"                  |
|                                                           |
| 이 설계의 목적:                                            |
| "__________________________________________ 을/를         |
|  일관되게 수행하기 위한 기준을 정의한다."                     |
|                                                           |
| 이것이 필요한 이유:                                        |
| "_____________________________________________________   |
|  _____________________________________________________"  |
|                                                           |
| 성공하면 어떤 모습인가?:                                    |
| "_____________________________________________________"  |
|                                                           |
+===========================================================+
|                                                           |
| [2] 규칙 (Rules) -- "어떤 기준을 따를 것인가?"              |
|                                                           |
| 반드시 지켜야 할 것 (Do):                                  |
| 1. ___________________________________________________   |
| 2. ___________________________________________________   |
| 3. ___________________________________________________   |
| 4. ___________________________________________________   |
|                                                           |
| 절대 하면 안 되는 것 (Don't):                              |
| 1. ___________________________________________________   |
| 2. ___________________________________________________   |
| 3. ___________________________________________________   |
|                                                           |
| Tip: "좋게 하라" 같은 모호한 표현 대신,                    |
|      "핵심 주제를 3가지 이내로 정리한다"처럼                 |
|      구체적으로 적으세요.                                   |
|                                                           |
+===========================================================+
|                                                           |
| [3] 맥락 (Context) -- "어떤 배경 정보가 필요한가?"          |
|                                                           |
| 대상/독자는 누구인가?                                      |
| "_____________________________________________________"  |
|                                                           |
| 이 작업은 어떤 상황에서 이루어지는가?                        |
| "_____________________________________________________"  |
|                                                           |
| 이 작업의 주기/빈도는? (예: 매주, 시험마다, 월 1회)          |
| "_____________________________________________________"  |
|                                                           |
| 참고할 기존 자료나 형식이 있는가?                            |
| "_____________________________________________________"  |
|                                                           |
| 성공의 기준은 무엇인가? (어떻게 되면 '잘 된 것'인가?)        |
| "_____________________________________________________"  |
|                                                           |
+===========================================================+
|                                                           |
| [4] 수준 검증 -- "내 설계서는 몇 수준인가?" (메타인지)       |
|                                                           |
| 잠깐 멈추고, 위에서 작성한 [1]~[3]을 다시 읽어보세요.       |
| 그리고 스스로 판단해 봅시다.                                |
|                                                           |
| 이 설계서는 현재 어떤 수준에 가까운가?                       |
|                                                           |
| [ ] 수준 1 -- 1회성 요청에 가까움                          |
|     ("해줘" 수준에서 크게 벗어나지 못함)                     |
|                                                           |
| [ ] 수준 2 -- 패턴은 있지만 반복 적용이 어려움              |
|     (대략적인 방향은 있으나 구체성이 부족)                   |
|                                                           |
| [ ] 수준 3 -- 이 설계서만으로 누구든(또는 AI가)             |
|     일관된 결과를 낼 수 있음                                |
|                                                           |
| 수준 3이 되려면 부족한 것은?:                               |
| "_____________________________________________________   |
|  _____________________________________________________"  |
|                                                           |
| --> 부족한 부분을 발견했다면, 위로 돌아가서 보완하세요!       |
|                                                           |
+===========================================================+
|                                                           |
| [5] 테스트 시나리오 -- "이대로 실행 가능한가?"              |
|                                                           |
| 다음 문장을 완성하세요:                                    |
|                                                           |
| "이 설계서를 처음 보는 사람(또는 AI)에게 건네면,            |
|  그 사람은 ________________________________________       |
|  을/를 ______________________________________________     |
|  수준으로 수행할 수 있을 것이다."                           |
|                                                           |
| 이 테스트에 자신이 있는가?                                 |
| [ ] 자신 있다 -- 핵심 정보가 충분히 담겨 있다               |
| [ ] 반반이다 -- 일부 정보가 더 필요할 것 같다               |
| [ ] 자신 없다 -- 많이 보완해야 할 것 같다                   |
|                                                           |
| "반반" 또는 "자신 없다"라면, 무엇이 부족한가?              |
| "_____________________________________________________"  |
|                                                           |
+===========================================================+
```

### 실습 진행 단계

| 단계 | 시간 | 활동 |
|------|------|------|
| 1단계 | 3분 | 반복 작업 선택 (위의 선택 가이드 활용) |
| 2단계 | 12분 | [1] 목적 + [2] 규칙 + [3] 맥락 작성 |
| 3단계 | 10분 | [4] 수준 검증 + [5] 테스트 시나리오 작성 |
| 4단계 | 5분 | 자기 점검 후 수정 (부족한 부분 보완) |

### 단계별 진행자 안내

**1단계 (3분) -- 반복 작업 선택**

> "5회차에서 수준 변환 연습을 한 과제를 그대로 사용해도 좋고, 새로 선택해도 좋습니다. 다만, 반복적으로 하는 일이어야 합니다. 1회성 과제보다는 '앞으로도 계속 하게 될 일'을 고르세요."

> **진행자 팁**: 너무 오래 고르지 않도록 "2분 안에 하나만 정하세요. 완벽한 선택이 아니어도 됩니다"라고 안내합니다.

**2단계 (12분) -- 목적, 규칙, 맥락 작성**

> "가장 중요한 단계입니다. 특히 규칙의 Do와 Don't를 쓸 때, '이것을 처음 보는 사람도 따라 할 수 있을 만큼 구체적으로' 쓰세요."

> **진행자 팁**: 학생들이 '규칙'을 쓸 때 가장 어려워합니다. 순회하면서 "그건 구체적으로 어떤 뜻이에요?"라고 질문하여 모호한 규칙을 구체화하도록 도와줍니다. 예를 들어, 학생이 "잘 써야 한다"라고 쓰면 "'잘'이 어떤 의미인가요? 분량? 구조? 표현?"이라고 물어봅니다.

**3단계 (10분) -- 수준 검증과 테스트 시나리오**

> "여기서 잠깐 멈추고, 여러분이 쓴 것을 '한 발 물러서서' 봐 주세요. 이것이 메타인지입니다. '나는 방금 뭘 썼고, 그게 충분한가?'를 스스로 판단하는 것입니다."

> **진행자 팁**: "수준 1에 가깝다"고 체크하는 학생이 있어도 괜찮습니다. "자기 설계의 수준을 정확히 인식하는 것 자체가 메타인지이고, 그것이 이 활동의 목적입니다"라고 격려합니다.

**4단계 (5분) -- 자기 점검 후 수정**

> "수준 검증에서 발견한 부족한 부분을 1~2곳만 수정해 보세요. 완벽하게 만들 필요는 없습니다. '어디가 부족한지 아는 것'이 중요합니다."

### 작성 예시: 학생 사례 2가지

아래는 학생들이 참고할 수 있는 예시입니다. 완벽한 모범답안이 아니라 '이런 방향으로 쓰면 된다'는 안내입니다.

**예시 A: 시험 공부 계획 수립**

> **목적**: "중간고사 2주 전부터 전 과목 학습 계획을 세우기 위한 기준을 정의한다."
>
> **규칙 (Do)**: 과목별 시간 비율은 취약도에 따라 배분 / 하루 총 공부 시간은 4시간 이내 / 매일 전날 복습 30분 포함 / 주말에는 모의 문제 풀이 시간 확보
>
> **규칙 (Don't)**: 하루에 한 과목만 몰아서 하지 않기 / 새벽 공부 계획 금지 / 이미 자신 있는 단원에 과도한 시간 배분 금지
>
> **맥락**: 고1 / 국영수과사 5과목 / 수학 이차함수 단원이 약함 / 평일 오후 4시~10시 가용 / 주말 오전 가용 / 목표: 전 과목 평균 80점 이상
>
> **수준 검증**: 수준 2~3 사이. 과목별 구체적인 단원 정보와 현재 성적 데이터가 추가되면 수준 3에 가까워질 것.

**예시 B: 독서 감상문 구조화**

> **목적**: "국어 수행평가용 독서 감상문을 일관된 구조로 작성하기 위한 기준을 정의한다."
>
> **규칙 (Do)**: 서론-본론-결론 3단 구조 / 본론에서 인상 깊은 장면 2가지 이상 인용 / 책의 내용과 나의 경험을 반드시 연결 / 800자 이상 1200자 이내
>
> **규칙 (Don't)**: 줄거리 요약에만 그치지 않기 / "재미있었다", "감동적이었다" 같은 막연한 감상 금지 / 인터넷 서평 베끼지 않기
>
> **맥락**: 고1 국어 수행평가 / 문학 작품 대상 / 선생님이 평가 (논리성, 창의성, 성실도) / 학기당 2회 작성 / 참고: 이전에 쓴 감상문 파일
>
> **수준 검증**: 수준 2. '좋은 감상문의 구체적 특징'에 대한 기준이 더 필요함. 예를 들어 "논리성이란 구체적으로 무엇인가?"를 정의해야 수준 3에 도달.

> **진행자 팁**: 예시를 보여줄 때 "이것이 정답"이라고 하지 않습니다. "이런 식으로 쓸 수 있다는 참고 자료"라고 안내합니다. 학생마다 선택한 과제가 다르므로 자기 상황에 맞게 적용하는 것이 중요합니다.

## 공유와 검증 (15분) -- "서로의 설계를 검증하자"

### 짝 교환 활동 (10분)

옆 사람(또는 다른 모둠)과 워크시트를 교환합니다.

**핵심 질문**: "이 설계서대로 AI에게 시키면, 원하는 결과가 나올까?"

다음 검증 체크리스트를 사용하여 피드백을 작성합니다.

```
+===========================================================+
|                                                           |
|           AI 협업 설계서 검증 체크리스트                     |
|                                                           |
+===========================================================+
|                                                           |
| 검증자 이름: ________________                              |
| 작성자 이름: ________________                              |
|                                                           |
+-----------------------------------------------------------+
|                                                           |
| [목적 검증]                                               |
| [ ] 목적이 한 문장으로 명확한가?                            |
| [ ] "무엇을 달성하려는지" 바로 이해되는가?                   |
|                                                           |
+-----------------------------------------------------------+
|                                                           |
| [규칙 검증]                                               |
| [ ] Do 규칙이 구체적인가?                                  |
|     ("좋게 써라" 같은 모호한 표현은 없는가?)                 |
| [ ] Don't 규칙이 있는가?                                   |
|     (경계가 설정되어 있는가?)                                |
| [ ] 규칙만 읽고 "어떻게 해야 하는지" 바로 알 수 있는가?      |
|                                                           |
+-----------------------------------------------------------+
|                                                           |
| [맥락 검증]                                               |
| [ ] 맥락 정보만 읽고도 상황을 이해할 수 있는가?              |
| [ ] 빠진 중요 정보가 있는가?                                |
|     (있다면 무엇인가: _______________________________ )    |
|                                                           |
+-----------------------------------------------------------+
|                                                           |
| [종합 판단]                                               |
| [ ] 이 설계서를 AI에게 건네면                               |
|     원하는 결과가 나올 것 같은가?                            |
|                                                           |
| [ ] "수준 3"에 가까운가, 아니면 아직 "수준 1~2"인가?         |
|     --> 현재 수준 판단: ___                                |
|                                                           |
+-----------------------------------------------------------+
|                                                           |
| 가장 좋은 점:                                             |
| _________________________________________________________  |
| _________________________________________________________  |
|                                                           |
| 개선하면 좋을 점:                                          |
| _________________________________________________________  |
| _________________________________________________________  |
|                                                           |
| 구체적 개선 제안 (1가지 이상):                              |
| _________________________________________________________  |
| _________________________________________________________  |
|                                                           |
+===========================================================+
```

**활동 순서**:

1. **(1분)** 짝과 워크시트를 교환한다
2. **(5분)** 검증 체크리스트를 작성한다 -- 체크만 하지 말고, "개선하면 좋을 점"과 "구체적 개선 제안"을 반드시 적는다
3. **(2분)** 서로 피드백을 설명한다 -- 구두로 보충 설명
4. **(2분)** 피드백을 반영하여 설계서를 1곳 이상 수정한다

> **진행자 팁**: 검증 활동이 '비판'이 아니라 '함께 개선'하는 것임을 강조합니다. "비판이 아니라 도움입니다. '이 부분이 더 구체적이면 좋겠다'는 것은 상대방의 설계서를 더 좋게 만들어주는 것입니다."

### 전체 토론 (5분)

검증 활동 후, 전체적으로 토론합니다.

> **진행자 발문**:
>
> "검증하면서 가장 많이 나온 피드백이 무엇이었나요?"
>
> (아마도: "규칙이 모호하다", "맥락 정보가 부족하다" 등)
>
> "규칙을 '구체적으로' 쓰는 것이 왜 그렇게 어려운가요?"
>
> (핵심 포인트: 구체적으로 쓰려면 **내가 무엇을 원하는지 정확히 알아야** 하기 때문)
>
> "'이 설계서대로 AI에게 시키면 될까?'라는 기준, 흥미롭지 않았나요? 그것이 바로 설계의 품질 기준입니다."

**진행자가 끌어내야 할 핵심 인사이트**:

> "설계서를 쓰는 것이 어려운 이유는 AI가 어려워서가 아닙니다. **내 생각이 아직 구조화되지 않았기 때문**입니다. 설계서를 쓰는 과정은 곧 내 생각을 정리하는 과정입니다. 이것이 Vygotsky가 말한 '비계'의 첫 번째 의미 -- 나를 위한 비계 -- 입니다."

---

## 정리 (5분) -- "오늘의 핵심"

### 핵심 한 줄 요약

> **"AI 협업 설계서 = 목적 + 규칙 + 맥락. 설계서를 쓰는 것은 AI를 위한 것이 아니라, 내 생각을 구조화하는 것이다."**

### 오늘의 키워드

| 키워드 | 의미 |
|--------|------|
| 목적 (Purpose) | "이 시스템은 왜 존재하는가?" -- 방향 설정 |
| 규칙 (Rules) | "어떤 기준을 따라야 하는가?" -- Do와 Don't |
| 맥락 (Context) | "판단에 필요한 배경 정보는?" -- 상황 설명 |
| 메타인지 | "내 설계서는 현재 몇 수준인가?" -- 자기 검증 |
| 비계 (Scaffolding) | 설계서는 나와 AI 모두에게 주는 구조적 지원 |

### 3줄 복습

학생들에게 오늘 배운 것을 3줄로 정리하게 합니다.

```
+-----------------------------------------------------+
|    오늘 배운 것 3줄 정리                               |
+-----------------------------------------------------+
|                                                     |
| 1. AI 협업 설계서의 3요소는 _______, _______, _______  |
|                                                     |
| 2. 설계서를 쓸 때 가장 어려웠던 것은 ________________  |
|                                                     |
| 3. 내 설계서의 현재 수준은 ___ 이고,                  |
|    수준 3이 되려면 ________________________________   |
|                                                     |
+-----------------------------------------------------+
```

### 다음 회차 예고: 7회차 -- "'만들어줘' vs '생각해봐'"

> "오늘 우리는 설계서를 '만들었습니다'. 다음 시간에는 드디어 AI와 실제로 대화를 해봅니다. 그런데, AI에게 말하는 방식에도 큰 차이가 있습니다. '만들어줘'라고 결과물을 바로 요청하는 것과, '생각해봐'라고 함께 탐색하는 것. 이 둘의 차이를 직접 체험해 보겠습니다. 오늘 만든 설계서가 그때 큰 힘이 될 것입니다."

> **진행자 팁**: 7회차에서 AI를 처음 사용하게 되므로, 학생들의 기대감을 높이되 "AI를 쓰는 것 자체가 목적이 아니라, 어떻게 쓰는가가 핵심"이라는 메시지를 함께 전달합니다.

## 진행자 가이드

### 시간 운영 요약

| 단계 | 배정 시간 | 최소 시간 | 유연 조정 |
|------|----------|----------|----------|
| 도입 | 10분 | 7분 | 복습이 빠르면 탐색으로 넘김 |
| 탐색 | 15분 | 12분 | 모둠 토론이 활발하면 1~2분 연장 가능 |
| 핵심 개념 | 15분 | 13분 | 사례 설명은 축약 가능 |
| 실습 | 30분 | 28분 | 핵심 시간, 절대 줄이지 않음 |
| 공유와 검증 | 15분 | 12분 | 전체 토론 축약 가능 |
| 정리 | 5분 | 3분 | 다음 회차 예고는 간략히 |

### 예상되는 학생 반응과 대처

| 예상 반응 | 대처 방법 |
|----------|----------|
| "목적을 한 문장으로 못 쓰겠어요" | "지금 하려는 일을 친구에게 한마디로 설명한다면 뭐라고 할까요?" |
| "규칙을 뭘 써야 할지 모르겠어요" | "지금까지 이 작업을 할 때 '이건 꼭 해야 해'라고 느낀 것은요? 반대로 '이건 하면 안 돼'라고 느낀 것은요?" |
| "맥락에 뭘 써야 하는지 모르겠어요" | "이 작업을 전혀 모르는 전학생에게 설명한다면, 어떤 배경을 알려줘야 할까요?" |
| "수준 3이 안 돼요 / 수준 1밖에 안 돼요" | "자기 수준을 정확히 아는 것이 메타인지이고, 그것만으로도 이 활동의 목적을 달성한 것입니다" |
| "이걸 왜 종이에 써요? AI에 직접 넣으면 안 돼요?" | "설계 없이 바로 AI에게 가면 '해줘' 수준에 머물게 됩니다. 먼저 생각을 구조화하는 연습을 하는 것이 이 수업의 목적입니다" |
| "설계서가 너무 길어지는데요?" | "길어지는 것은 괜찮습니다. 오히려 좋은 신호예요. 다만, 각 항목이 명확한지를 점검해 보세요" |

### 진행자가 반드시 지켜야 할 것

1. **정답을 말하지 않는다**: 학생이 스스로 구조를 발견하도록 질문으로 유도합니다
2. **완벽을 기대하지 않는다**: "이것은 초안입니다. 중요한 것은 '목적-규칙-맥락'이라는 구조로 생각해 본 것 자체입니다"
3. **AI를 직접 사용하지 않는다**: 이 회차의 핵심은 '설계서 작성'이지, AI 사용이 아닙니다
4. **메타인지를 강조한다**: 수준 검증 단계에서 "자기 설계를 스스로 평가하는 것"의 가치를 반복적으로 언급합니다
5. **모든 수준의 결과를 존중한다**: 수준 1이라도 "그것을 인식한 것이 중요하다"고 격려합니다

### 준비물

- 워크시트 인쇄물 (1인 2장: 설계서 + 검증 체크리스트)
- 반복 작업 선택 가이드 인쇄물 (또는 화면 공유)
- 필기도구
- 타이머 (단계별 시간 안내용)
- (선택) 예시 설계서를 미리 화면에 띄워 둘 수 있도록 준비

### 보조 질문 모음 (토론이 침묵으로 빠질 때)

탐색 단계:
- "여러분이 카페에서 알바하는데, 사장님이 '가게 잘 운영해'라고만 하고 출장을 가면 어떨까요? 뭘 알아야 할까요?"
- "친구에게 '내 대신 발표해줘'라고 부탁한다면, 그 친구에게 최소한 뭘 알려줘야 할까요?"

핵심 개념:
- "목적 없이 규칙만 있으면 어떻게 될까요? 반대로, 목적만 있고 규칙이 없으면?"
- "맥락이 빠지면 어떤 일이 벌어질까요? 예를 들어 '감상문 써줘'라고만 했는데, 초등학생 과제용인지 대학 리포트인지 모른다면?"

실습:
- "규칙의 Do를 쓸 때, '이것을 처음 보는 사람이 바로 따라 할 수 있을 만큼 구체적인가?'를 자문해 보세요"
- "Don't를 쓰기 어려우면, '이전에 이 작업을 했을 때 실패한 경험'을 떠올려 보세요. 그 실패 원인이 Don't가 됩니다"

공유와 검증:
- "설계서를 읽었을 때, '이 부분은 무슨 뜻이지?'라고 헷갈리는 곳이 있었나요? 그곳이 개선 포인트입니다"
- "만약 여러분이 AI라면, 이 설계서만 보고 일을 할 수 있을까요?"

## 이번 회차의 교육적 의미

### Bloom's Taxonomy 관점

이번 회차는 **평가(Evaluate)** 수준에 해당합니다.

```
기억(Remember)     -- 1회차에서 CT 4요소를 알았음
이해(Understand)   -- 2~3회차에서 분해, 패턴, 추상화를 이해했음
적용(Apply)        -- 4~5회차에서 실제 문제에 적용했음
분석(Analyze)      -- 5회차에서 3수준을 분석적으로 비교했음
--> 평가(Evaluate) -- 6회차: 자기 설계서의 수준을 판단하고 검증   <-- 여기
창조(Create)       -- 8~10회차에서 자기만의 시스템을 만들 예정
```

### 연결 구조

```
5회차                     6회차                     7회차
"수준이 있다는 것         "수준 3을 만드는          "설계서를 들고
 을 알았다"               방법을 익혔다"            AI와 대화한다"
(인식)            -->     (설계)           -->     (실행)
```

5회차에서 발견한 '수준'의 개념이 6회차에서 '설계서'라는 구체적 도구로 연결되고, 7회차에서 실제 AI와의 대화로 확장됩니다. 6회차는 이 흐름의 중간 다리 역할을 합니다.

## 참고 자료

### AI 협업 설계서 3요소 요약표

| 요소 | 핵심 질문 | 빠지면 어떻게 되는가 |
|------|----------|-------------------|
| 목적 (Purpose) | "왜 하는가?" | AI가 방향을 모름. 엉뚱한 결과물이 나옴 |
| 규칙 (Rules) | "어떻게 해야 하는가?" | AI가 제멋대로 판단함. 원하지 않는 것도 포함됨 |
| 맥락 (Context) | "어떤 상황인가?" | AI가 일반적인 결과를 줌. 내 상황에 안 맞음 |

### 학생 사례 추가 아이디어

학생들이 선택할 수 있는 반복 작업의 구체적 예시입니다.

|------|----------|------------------|

| 글쓰기 | 생활기록부 자율활동 기록 | 어떤 구조? 어떤 표현? 금지 사항? |
| 발표 준비 | 탐구 보고서 발표 슬라이드 | 슬라이드 수? 핵심 메시지? 시각 자료? |

| 자기관리 | 주간 학습 회고 | 어떤 항목을 돌아보는가? 반성만? 계획도? |
