    Layer 1 — 구조적 사고력

    1회차: AI 시대, 무엇이 남을까?¶

    AI가 대체할 수 없는 능력은 무엇인지 탐색하고, Computational Thinking의 4요소를 처음 만나봅니다.

    90분 Layer 1 — 1/4 AI 도구 미사용

    학습 목표¶

    1. AI 시대에 '실행 능력'의 가치가 변화하고 있음을 사례를 통해 설명할 수 있다
    2. Computational Thinking(구조적 사고)의 개념과 4요소를 자기 말로 설명할 수 있다
    3. 일상의 문제 하나를 하위 문제로 분해하는 첫 경험을 할 수 있다

    도입 — "왜 이것이 필요한가?"¶

    여러분, 반갑습니다. 지금부터 함께할 수업의 이름은 'AI 시대의 구조적 사고'입니다. 이름이 좀 어렵게 느껴질 수도 있는데, 걱정하지 마세요. 코딩을 배우는 것도 아니고, 수학 공식을 외우는 것도 아닙니다. 우리가 할 일은 딱 하나입니다 -- 생각해보는 것.

    시작하기 전에 스스로 떠올려 봅시다.

    생각해 보기

    • 영어 숙제할 때 번역기를 써본 적이 있나요?
    • 발표 자료 만들 때 AI한테 내용을 물어본 적은요?
    • 독서 감상문 쓸 때 줄거리를 AI로 정리해 본 적은요?

    아마 하나쯤은 경험이 있을 겁니다. AI를 써본 적이 없다고 해도 전혀 괜찮습니다. 이 수업은 AI를 잘 쓰는 법을 가르치는 게 아니거든요.

    AI가 대신 해주는 것들¶

    사실 방금 이야기한 것들 -- 번역, 글쓰기, 정보 정리 -- 이런 것들을 AI가 꽤 잘합니다. 요즘 AI가 무엇을 할 수 있는지 정리해 볼까요?

    영역 AI가 할 수 있는 것 예시
    글쓰기 감상문, 보고서, 편지 초안 작성 "이 책의 감상문 써줘"
    번역 거의 모든 언어 간 번역 "이 영어 지문 해석해줘"
    코딩 프로그램 작성, 오류 수정 "파이썬으로 계산기 만들어줘"
    이미지 그림, 포스터, 디자인 생성 "학교 축제 포스터 만들어줘"
    정보 정리 요약, 비교표, 마인드맵 구성 "이 단원 핵심 정리해줘"

    핵심 질문¶

    이렇게 보면 AI가 못하는 게 거의 없는 것 같죠? 그런데 여기서 한 가지 질문이 생깁니다.

    "AI가 이렇게 많은 것을 대신해 준다면, 우리에게 남는 능력은 무엇일까?"

    지금 바로 대답하지 않아도 됩니다. 이 질문을 가슴에 품고 다음으로 넘어가 봅시다.

    비유로 생각해 보기¶

    과거에는 영어를 잘하는 것 자체가 큰 능력이었습니다. 통역사, 번역가가 귀한 직업이었죠. 그런데 지금은 어떤가요? 번역기가 정말 잘 되니까, '영어를 할 줄 아는 것' 자체보다 '영어로 무슨 이야기를 할 것인가'가 더 중요해졌습니다.

    AI 시대에도 비슷한 변화가 일어나고 있습니다.

    탐색 — "먼저 생각해보자"¶

    이제 여러분이 직접 생각해볼 차례입니다.

    개인 탐색 활동¶

    다음 질문에 대해 최소 3가지를 적어 보세요. 거창하지 않아도 됩니다.

    "AI가 아무리 발전해도, 인간이 직접 해야 하는 일이 있다면 그것은 무엇일까요?"

    안내

    정답을 맞히는 게 아닙니다. 친구한테 카톡 보내듯 편하게 적어도 괜찮아요. 틀린 답은 없습니다.

    여기에 3가지 이상 적어 보세요
    예시 답변

    다른 학생들은 이런 답변을 적기도 했습니다:

    • "감정을 느끼는 것" / "공감"
    • "친구를 사귀는 것" / "관계"
    • "결정을 내리는 것" / "선택"
    • "무엇이 중요한지 판단하는 것"
    • "문제를 찾아내는 것"
    • "새로운 아이디어를 내는 것"
    • "책임지는 것"
    • "운동하는 것" (신체 활동)

    여러분의 답과 비교해 보세요. 비슷한 것도 있고, 다른 것도 있을 겁니다. 모두 의미 있는 답입니다.

    함께 생각 나누기¶

    혼자 적어본 것을 친구들과 나누어 봅시다. 다음 세 가지를 함께 이야기해 보세요.

    1. "우리의 답에서 겹치는 게 있나?" -- 공통점을 찾아봅시다
    2. "AI가 '할 수는 있지만 맡기면 안 되는 것'과 '진짜 못하는 것'은 다른가?" -- 구분해 봅시다
    3. "우리의 답을 한 단어로 묶는다면?" -- 핵심을 뽑아봅시다

    토론이 막힐 때

    "예를 들어, AI가 시를 쓸 수 있긴 한데 그게 진짜 '창작'이라고 할 수 있을까요?"처럼 구체적인 사례를 떠올려 보세요.

    탐색 결과 정리¶

    여러분이 찾은 것들을 묶어보면, 크게 몇 가지 덩어리가 보일 겁니다.

    클러스터링 예시

    감정/관계 판단/결정 새로운 것 문제를 찾고 정리하는 것
    공감 선택 창의력 문제 발견
    사랑 책임 아이디어 구조 잡기
    우정 가치 판단 상상력 계획 세우기

    감정과 관계에 대한 것, 판단과 결정에 대한 것, 그리고 문제를 발견하고 구조를 잡는 것. 이 모든 것이 AI 시대에 중요한 능력입니다.

    그런데 오늘 우리가 집중할 영역은 바로 마지막 부분입니다 -- 문제를 정의하고 구조화하는 능력.

    핵심 개념 — Computational Thinking이란?¶

    탐색 결과에서 프레임워크로¶

    방금 여러분이 탐색에서 찾은 것들 -- '문제를 발견하는 것', '구조를 잡는 것', '판단하는 것' -- 이것들을 묶어서 설명하는 하나의 프레임워크가 있습니다. 컴퓨터 과학에서 Computational Thinking(컴퓨팅 사고력, 구조적 사고)이라고 부르는 것입니다.

    핵심 개념

    이름에 '컴퓨터'가 들어가니까 코딩 이야기 같죠? 그런데 아닙니다. 2006년 미국의 Jeannette Wing 교수가 이 개념을 제안했을 때, '프로그래밍을 잘하는 것'이 아니라 '누구나 가져야 할 문제 해결 사고방식'이라고 설명했습니다.

    수학 시간에 공식을 외우는 것이 아니라 '수학적으로 사고하는 법'을 배우는 것과 같은 맥락이에요.

    Computational Thinking의 4요소¶

    :hocho:

    분해 Decomposition¶

    큰 문제를 더 작은, 다루기 쉬운 문제로 나눈다

    패턴 인식 Pattern Recognition¶

    반복되는 구조나 규칙성을 찾는다

    추상화 Abstraction¶

    핵심만 남기고 불필요한 세부사항을 걸러낸다

    알고리즘 설계 Algorithm Design¶

    해결 절차를 단계별로 구성한다

    학교생활 사례로 이해하기¶

    이론만 보면 어렵죠? 여러분에게 익숙한 상황으로 바꿔봅시다.

    사례 1: 기말고사 준비

    CT 요소 적용 예시
    분해 "기말고사 준비"라는 큰 문제를 → 국어, 수학, 영어, 과학, 사회 과목별로 나눈다
    패턴 인식 "매번 시험에서 수학 서술형을 틀린다" → 반복되는 약점 패턴을 발견한다
    추상화 수학 서술형의 핵심 = "풀이 과정을 논리적 순서로 쓰는 것" → 핵심만 추출한다
    알고리즘 설계 "1단계: 문제 유형 파악 → 2단계: 공식 적용 → 3단계: 풀이 순서 정리 → 4단계: 검산"

    사례 2: 학교 축제 준비

    CT 요소 적용 예시
    분해 "학교 축제"를 → 무대 공연, 부스 운영, 홍보, 예산 관리, 청소/정리로 나눈다
    패턴 인식 작년 축제와 올해 축제의 준비 과정이 비슷하다 → 공통 구조를 발견한다
    추상화 어떤 행사든 "기획 → 준비 → 실행 → 정리"의 구조로 요약할 수 있다
    알고리즘 설계 "D-30: 기획안 확정 → D-14: 역할 분담 → D-7: 리허설 → D-Day: 실행"

    사례 3: 동아리 가입 결정

    CT 요소 적용 예시
    분해 "동아리 선택"을 → 내 관심사, 시간표, 활동 내용, 선배 분위기로 나눈다
    패턴 인식 "내가 좋아하는 활동은 항상 만들기가 들어간다" → 자기 패턴 발견
    추상화 결국 핵심은 "내가 즐길 수 있으면서 + 배울 수 있는 곳"으로 요약
    알고리즘 설계 "1. 후보 3개 선정 → 2. 체험 참가 → 3. 기준표로 비교 → 4. 최종 결정"

    "왜 이것이 AI 시대에 더 중요한가?"¶

    여기서 한 가지 질문이 남습니다. 구조적 사고는 AI가 나오기 전에도 중요했는데, 왜 AI 시대에 더 중요할까요?

    역량 AI 대체 가능성 사람의 역할
    번역하기, 글 초안 쓰기, 코드 작성 높음 -- AI가 빠르고 잘 함 결과를 검토하고 방향을 정함
    문제를 정의하기 낮음 -- AI는 스스로 문제를 발견하지 못함 핵심 역량
    구조를 설계하기 중간 -- AI가 도울 수는 있음 최종 판단과 선택은 사람이
    맥락을 이해하고 가치를 판단하기 낮음 -- AI는 맥락을 모름 핵심 역량
    "AI가 '실행'을 빠르게 해줄수록, '무엇을 실행할지 정의하고 구조화하는 능력'의 가치는 올라갑니다. 이것이 우리가 키울 핵심 능력입니다."
    스스로 점검하기
    • "그러면 공부를 안 해도 되나요?"라는 생각이 들었나요?
    • 공부의 '의미'가 바뀌는 겁니다. 영어 단어 100개를 외우는 것보다, 그 단어들로 어떤 이야기를 구성할지 생각하는 능력이 더 중요해진다는 뜻입니다.
    • 물론 기본 지식은 여전히 필요합니다 -- 생각할 재료가 있어야 구조를 짤 수 있으니까요.

    실습 — "구조를 설계해보자"¶

    자, 이제 직접 해볼 시간입니다. 오늘 실습은 코드를 쓰는 것이 아닙니다. AI를 쓰는 것도 아닙니다. 학교 축제 기획을 구조적으로 분해하는 '설계서'를 작성하는 것입니다.

    실습의 핵심

    중요한 것은 결과가 아니라 '왜 그렇게 나누었는가'를 설명할 수 있는 것입니다. 같은 축제 기획이라도 사람마다 다르게 나눌 수 있고, 그것이 정상입니다. 정답은 없습니다.

    과제¶

    여러분의 학교에서 축제를 열게 되었습니다. 여러분은 축제 기획 위원회의 위원장입니다. '축제를 성공적으로 진행하라'는 큰 문제를 하위 문제로 쪼개서, 실제로 실행 가능한 계획의 뼈대를 만들어 보세요.

    다른 주제도 괜찮아요

    축제 대신 체육대회, 학급 회식, 수학여행 계획 등 다른 학교 행사로 바꿔도 됩니다. 아래 표에서 골라보세요.

    주제 문제 예시
    체육대회 "학급 체육대회를 준비하고 성공적으로 진행하기"
    수학여행 "2박 3일 수학여행 일정을 기획하기"
    동아리 발표회 "동아리 연말 발표회를 기획하고 실행하기"
    학급 영화제 "학급 단편영화를 제작하고 상영하기"

    1 문제 정의¶

    우리가 해결할 문제를 한 문장으로 써 봅시다.

    "우리 학교 축제를 성공적으로 기획하고 진행하려면 ____를 해결해야 한다."

    '성공적'이라는 것은 구체적으로 무엇을 뜻할까요? (예: 모든 학생이 즐기는 것, 사고 없이 끝나는 것, 예산 내 진행 등)

    2 분해 — 큰 문제를 작은 문제로 쪼개기¶

    CT 요소: 분해(Decomposition)

    축제 기획을 하위 문제로 나눠 봅시다. (최소 4개, 최대 7개)

    각 하위 문제에 대해 "이것이 해결되면 무엇이 가능해지는가?"도 함께 적어 보세요.

    하위 문제 1: → 이것이 해결되면: 하위 문제 2: → 이것이 해결되면: 하위 문제 3: → 이것이 해결되면: 하위 문제 4: → 이것이 해결되면: (필요하면 5~7까지 더 적어 보세요)

    막힐 때 도움이 되는 질문

    • "축제 전날에 꼭 끝나 있어야 하는 것은?"
    • "당일에만 할 수 있는 것은?"
    • "축제 끝나고 해야 하는 것은?"

    3 분해 기준 — "왜 이렇게 나누었나?"¶

    CT 요소: 추상화(Abstraction)

    나는 어떤 기준으로 문제를 나누었나요? 해당하는 것을 골라봅시다.

    • 시간 순서대로 (준비 → 당일 → 뒷정리)
    • 담당 영역별로 (무대, 부스, 홍보, 예산 등)
    • 대상별로 (학생, 선생님, 외부 손님 등)
    • 기타: ________
    이 기준을 선택한 이유: 다른 기준으로 나누었다면 어떻게 달라졌을까?

    4 하위 문제 사이의 관계¶

    CT 요소: 알고리즘 설계(Algorithm Design)

    위에서 나눈 하위 문제들의 관계는 어떤가요?

    • 순서대로 해결해야 한다 (1번 끝나야 2번 시작)
    • 동시에 진행할 수 있다 (여러 팀이 동시 작업)
    • 일부는 순서대로, 일부는 동시에 (혼합)
    아래에 간단한 순서도를 그려 봅시다. (화살표로 연결하거나, 동시에 진행할 것은 나란히 적어 주세요) [시작] → ( ) → ( ) → ... → [완료]

    안내

    순서도가 못생겨도 전혀 괜찮습니다! 대충이라도 순서가 보이면 됩니다.

    5 패턴 발견¶

    CT 요소: 패턴 인식(Pattern Recognition)

    이 축제 기획과 비슷한 구조의 다른 활동이 있나요?

    "____________________ 와(과) 구조가 비슷하다. 왜냐하면 둘 다 ____________________ 이기 때문이다." (예: 수학여행 계획, 체육대회 준비, 동아리 발표회 등)

    6 자기 검증¶

    작성한 설계서를 스스로 점검해 봅시다.

    • 하위 문제를 모두 해결하면 축제를 열 수 있는가?
    • 빠뜨린 것은 없는가? (혹시 빠진 게 있다면: ___)
    • 하위 문제끼리 겹치는 부분은 없는가?
    • 누군가에게 이 설계서를 보여주면 이해할 수 있을 만큼 구체적인가?

    공유와 검증 — "서로의 설계를 검증하자"¶

    이제 여러분이 만든 설계서를 다른 친구와 교환해서 검증할 시간입니다. 다른 사람의 눈으로 보면 내가 놓친 것이 보이거든요.

    6 종합 피드백¶

    이 설계서에서 가장 잘한 점 한 가지: 하나만 바꾼다면 이것을 바꿔보면 좋겠다:

    좋은 피드백 쓰는 법

    피드백을 쓸 때, '잘했다/못했다'가 아니라 '이 부분이 좋았고, 이 부분은 이렇게 하면 더 좋을 것 같다'는 식으로 써 주세요. 서로를 평가하는 게 아니라 서로의 생각을 발전시켜주는 겁니다.

    좋은 피드백 문장 예시:

    • "OO 부분이 구체적이어서 좋았습니다"
    • "혹시 OO은 빠진 건 아닐까요?"
    • "OO과 OO이 겹치는 것 같은데, 하나로 합치면 어떨까요?"

    피드백을 받은 후¶

    피드백을 받은 후 스스로 돌아봅시다:

    • "피드백 중에서 '아, 그걸 놓쳤네'라고 느낀 것이 있나요?"
    • "내 설계서에서 수정하고 싶은 부분이 생겼나요?"

    기억하세요

    같은 문제라도 사람마다 다르게 나눌 수 있습니다. 어떤 분해가 '정답'인 게 아니라, 다양한 관점으로 나눌 수 있다는 것 자체가 중요합니다. "이렇게 다르게 나눌 수도 있구나"를 발견하는 것이 이 활동의 핵심입니다.

    정리 — "오늘의 핵심"¶

    "AI 시대에 남는 능력은 문제를 정의하고, 분해하고, 구조화하는 힘 — Computational Thinking이다."

    오늘의 키워드 정리¶

    키워드 한 줄 설명
    Computational Thinking 문제를 구조적으로 사고하는 능력 -- 코딩 능력이 아님
    분해 (Decomposition) 큰 문제를 작은 문제로 나누는 것
    패턴 인식 (Pattern Recognition) 반복되는 구조나 규칙을 찾는 것
    추상화 (Abstraction) 핵심만 남기고 불필요한 것을 걸러내는 것
    알고리즘 설계 (Algorithm Design) 해결 절차를 단계별로 만드는 것
