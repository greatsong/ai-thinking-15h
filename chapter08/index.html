    8회차: 나만의 AI 활용 시스템 만들기

    Layer 2 — AI 협업 설계력 # 8회차: 나만의 AI 활용 시스템 만들기

    결과물 하나를 만드는 사람이 아니라, 결과물을 만드는 시스템을 설계하는 사람이 되어 봅시다. Layer 2의 마지막 회차에서 지금까지 배운 모든 것을 하나로 합칩니다.

    8/10회차 Layer 2 종합 Bloom's: 평가(Evaluate)

    🎯 이번 회차의 학습 목표¶

    1. 생성 장치(Harness)의 개념을 이해하고, 1회성 결과물과 반복 가능한 시스템의 차이를 설명할 수 있다
    2. 학교생활 속 반복 업무 하나에 대한 완전한 AI 활용 시스템(생성 장치)을 설계할 수 있다
    3. Layer 1의 구조적 사고력과 Layer 2의 AI 협업 설계력을 통합하여 적용할 수 있다

    🎬 지금까지의 여정 돌아보기¶

    8회차는 Layer 2의 마지막 회차이자, 5~7회차에서 하나씩 배운 개념들을 모두 합쳐서 하나의 작동하는 시스템을 만드는 시간입니다. Layer 1에서 익힌 구조적 사고력까지 통합해서, 배운 모든 것을 하나의 산출물로 완성해 봅시다.

    회차 배운 것 핵심 한 줄
    5회차 AI 활용의 3가지 수준 "숙제 해줘"부터 "시스템을 설계해줘"까지, 시키는 방법에도 수준이 있다
    6회차 AI 협업 설계서 (목적-규칙-맥락) AI에게 잘 시키려면, "왜-어떻게-무엇을" 구조화한 설계서가 필요하다
    7회차 탐색적 대화 "만들어줘"보다 "생각해봐"가 더 좋은 결과를 만든다
    8회차 생성 장치(Harness) 이 모든 것을 하나의 반복 가능한 시스템으로 합친다

    🔍 두 가지 요리사 이야기¶

    본격적인 학습에 앞서, 비유 하나를 생각해 봅시다.

    요리사 A는 손님이 올 때마다 인터넷에서 레시피를 검색합니다.

    • "오늘은 된장찌개 만들어야지..." → 검색 → 레시피 따라 하기
    • "내일은 김치볶음밥이네..." → 검색 → 또 다른 레시피 따라 하기
    • 매번 처음부터 찾고, 매번 다른 결과가 나옵니다.

    요리사 B는 자기만의 요리 노트를 가지고 있습니다.

    • 자주 만드는 메뉴 20개의 기본 기준이 정리되어 있습니다
    • "된장찌개: 된장 2큰술, 두부 반 모, 끓이기 15분, 마지막에 대파"
    • 재료가 바뀌어도, 기준이 있으니 일관된 맛이 나옵니다
    • 새로운 메뉴도 기존 기준을 응용해서 빠르게 추가합니다
    생각해 봅시다: 여러분이 식당 사장이라면?

    A와 B 중 누구를 고용하고 싶나요? 그 이유는 무엇인가요?

    대부분 B를 선택할 것입니다. "일관성", "효율", "시간 절약" 같은 이유를 생각해 보셨을 거예요.

    그렇다면 이것을 AI 활용에 적용해 봅시다.

    • 요리사 A처럼: 필요할 때마다 AI에게 새로 부탁하기 ("독서 감상문 써줘", "발표 자료 만들어줘")
    • 요리사 B처럼: 한 번 기준을 만들어두고 반복 사용하기 ("독서 감상문 작성 시스템: 구조-관점-분량 기준 설정")
    오늘 학습의 핵심은 요리사 B의 방식, 즉 "나만의 AI 활용 시스템"을 만드는 것입니다. 이것이 바로 생성 장치(Harness)입니다.

    🔍 탐색: 학교생활에서 반복되는 일¶

    🧠 개인 탐색 활동: "반복되는 일" 브레인스토밍¶

    여러분의 학교생활을 떠올려 봅시다. 아래 영역을 참고하면서, "반복되는 일"을 최대한 많이 적어 보세요. 정답이 없습니다. 떠오르는 대로 적어 주세요.

    영역 반복되는 일 (예시 참고)
    학습 주간 학습 정리, 시험 오답 분석, 수행평가 준비, 교과서 요약...
    발표/글쓰기 발표 자료 준비, 독서 감상문, 보고서 작성, 자기소개서...
    동아리/활동 동아리 회의록, 활동 보고서, 행사 기획안, 홍보물 제작...
    일상/기타 시간표 관리, 진로 탐색 정리, 일기/기록, 시험 일정 관리...

    떠오르지 않을 때 도움이 되는 질문

    • "지난 한 달 동안 비슷한 작업을 두 번 이상 한 것이 있나요?"
    • "매주 또는 매달 정기적으로 해야 하는 것이 있나요?"
    • "할 때마다 '이거 또 해야 하나...'라고 느꼈던 적이 있나요?"
    한 걸음 더: 시스템이 있다면 뭐가 달라질까?

    작성한 목록을 보면서 다음 두 가지 질문을 스스로에게 던져 보세요.

    1. "이것을 매번 처음부터 하고 있었나요?" — 이미 나만의 기준이 있었나요, 아니면 매번 새로 시작했나요?
    2. "이것을 시스템으로 만들 수 있다면?" — 시간이 절약될까요? 결과물의 품질이 일관적이 될까요? 다른 사람도 같은 시스템을 사용할 수 있을까요?

    📌 핵심 개념: 생성 장치(Harness)란 무엇인가?¶

    탐색 활동에서 여러분은 "반복되는 일"과 "시스템으로 만들면 좋겠다"는 생각을 했습니다. 이제 이것을 정확한 개념으로 정리해 봅시다.

    생성 장치(Harness)란, 결과물 하나를 만드는 것이 아니라 결과물을 반복적으로 만들어내는 구조와 기준을 말합니다.

    결과물 vs 생성 장치 비교¶

    두 가지 접근 방식을 비교해 봅시다.

    방식 1: 매번 새로 만들기 (결과물 중심)

    [1주차]  "시험 오답 정리해줘"  →  결과물 A
[2주차]  "시험 오답 정리해줘"  →  결과물 B (형식이 다름)
[3주차]  "시험 오답 정리해줘"  →  결과물 C (또 다른 형식)
                ↓
    매번 다른 결과, 매번 새로 설명, 품질 들쑥날쑥

    방식 2: 기준을 설계하고 반복 사용하기 (생성 장치)

    [설계 단계]  기준 설계 → "나의 오답 분석 시스템" 완성
                │
                │  ┌─ 분류 기준: 개념 오류 / 계산 실수 / 문제 해석 오류
                │  ├─ 분석 질문: "왜 틀렸는가?" "어떤 개념이 부족한가?"
                │  ├─ 출력 형식: 과목-단원-문제유형-원인-복습계획
                │  └─ 우선순위: 같은 유형 3회 이상 틀린 것 먼저
                │
[1주차]  시스템에 데이터 입력 → 일관된 결과물 A
[2주차]  시스템에 데이터 입력 → 일관된 결과물 B
[3주차]  시스템에 데이터 입력 → 일관된 결과물 C
                ↓
    기준이 있으니 일관된 품질, 기준만 개선하면 계속 발전

    핵심 차이 정리¶

    구분 결과물 중심 생성 장치 중심
    초기 투자 적음 (바로 시작) 많음 (기준 설계 필요)
    반복 시 효율 매번 비슷한 시간 소요 점점 빨라짐
    결과 품질 들쑥날쑥 일관적, 점진적 향상
    다른 사람이 사용 어려움 (내 머릿속에만 있음) 가능 (기준이 문서화됨)
    개선 방법 전체를 다시 만듦 기준만 업데이트
    비유 매번 레시피 검색 나만의 요리 노트

    이미 생성 장치를 사용하고 있을 수도 있습니다

    노트 필기 양식, 시험 공부 루틴, 운동 기록표 같은 것들도 일종의 생성 장치입니다. "생성 장치"라는 말이 거창하게 느껴질 수 있지만, 사실 이미 하고 있는 것의 확장이라고 생각하면 됩니다.

    Layer 1 + Layer 2 통합: 생성 장치를 만드는 과정¶

    여기서 중요한 것이 있습니다. 생성 장치는 그냥 만들어지지 않습니다. 지금까지 배운 것이 모두 필요합니다.

    ┌────────────────────────────────────────────────────┐
│              나만의 AI 활용 시스템                    │
│                                                    │
│   [Layer 1: 구조적 사고력]                           │
│    ① 문제 분해    — 반복 업무를 하위 요소로 쪼갠다      │
│    ② 패턴 인식    — 매번 반복되는 공통 구조를 찾는다    │
│    ③ 추상화       — 핵심 기준만 추출한다               │
│    ④ 절차 설계    — 처리 순서를 정한다                 │
│          ↓                                         │
│   [Layer 2: AI 협업 설계력]                           │
│    ⑤ 설계서 작성  — 목적/규칙/맥락을 구조화한다        │
│    ⑥ 탐색적 대화  — AI와 함께 시스템을 검증한다        │
│          ↓                                         │
│   [완성] 생성 장치 (Harness)                         │
│    → 반복 사용 가능한 AI 활용 시스템                   │
└────────────────────────────────────────────────────┘

    즉, 생성 장치를 만든다는 것은 Layer 1과 Layer 2를 통합하는 것입니다.

    • Layer 1 없이는: 문제를 쪼개지 못하니, 무엇을 시스템화해야 하는지 모릅니다
    • Layer 2 없이는: AI에게 어떻게 시켜야 하는지 모르니, 시스템이 작동하지 않습니다
    • 둘을 합쳐야: 비로소 "작동하는 생성 장치"가 완성됩니다

    학교생활 사례 3가지¶

    이해를 돕기 위해 구체적인 사례를 살펴봅시다. 이 사례들이 정답은 아닙니다. "이런 형태가 가능하다"는 것을 보여주는 것이니, 여러분의 상황에 맞게 변형하면 됩니다.

    사례 1: 주간 학습 정리 시스템

    • 문제 분해(L1): 과목별 정리 → 핵심 개념 추출 → 이해도 자기 평가 → 다음 주 계획
    • 설계서(L2): 목적(매주 학습 점검), 규칙(과목당 핵심 3개, 이해도 상/중/하), 맥락(고1 문과, 현재 중간고사 3주 전)
    • 생성 장치: 매주 금요일, 이 기준으로 AI에게 정리를 요청하면 일관된 주간 정리가 나옴

    사례 2: 발표 자료 준비 시스템

    • 문제 분해(L1): 주제 선정 → 자료 조사 → 구조 잡기 → 슬라이드 구성 → 발표 연습
    • 설계서(L2): 목적(수업 발표), 규칙(슬라이드 7장 이내, 한 장에 핵심 1개, 마지막은 질문 유도), 맥락(10분 발표, 고등학생 청중)
    • 생성 장치: 어떤 주제든 이 기준에 맞춰 AI와 함께 발표 자료를 구성할 수 있음

    사례 3: 독서 기록 시스템

    • 문제 분해(L1): 책 정보 → 핵심 내용 정리 → 인상 깊은 구절 → 나의 생각 → 다른 책과 연결
    • 설계서(L2): 목적(독서 습관 + 글쓰기 연습), 규칙(핵심 내용 3문장, 인상 구절 2개, 나의 생각 5문장 이상), 맥락(한 달에 2권 목표)
    • 생성 장치: 책을 읽을 때마다 같은 구조로 기록하고, AI가 기존 기록과 연결해줌

    🛠️ 실습: "나의 AI 활용 시스템" 설계¶

    이제 여러분이 직접 만들어볼 차례입니다. 이 실습은 Layer 2의 최종 산출물입니다. 지금까지 배운 모든 것을 하나로 합치는 활동입니다.

    📋 나의 AI 활용 시스템 설계서

    준 반복 업무 선택

    앞서 탐색 활동에서 브레인스토밍한 목록 중 하나를 골라 주세요.

    **선택 기준** (아래 3가지 중 2가지 이상 해당되는 것을 고르세요): - [ ] 한 달에 2회 이상 반복되는가? - [ ] 매번 비슷한 구조로 진행되는가? - [ ] AI가 도우면 시간이 절약되거나 품질이 올라갈 수 있는가?
    내가 선택한 반복 업무:
    선택 이유:

    1 문제 분해 — Layer 1 적용

    선택한 반복 업무를 구조적으로 분해해 봅시다. 2~3회차에서 배운 분해와 패턴 인식을 적용합니다.

    **(1) 이 업무를 하위 단계로 쪼개 주세요** (최소 4단계) | 순서 | 하위 단계 | 구체적 내용 | |------|----------|-----------| | 1 | | | | 2 | | | | 3 | | | | 4 | | | | 5 | | | **(2) 분해 점검 (MECE 확인)** - [ ] 빠진 단계가 없는가? (전체 포괄적) - [ ] 겹치는 단계가 없는가? (상호 배타적) - [ ] 이 순서대로 하면 업무가 완성되는가? **(3) 각 단계에서 AI가 도울 수 있는 부분에 표시해 주세요** | 하위 단계 | AI가 도울 수 있는가? | AI의 역할 | |----------|-------------------|----------| | 단계 1 | O / X | | | 단계 2 | O / X | | | 단계 3 | O / X | | | 단계 4 | O / X | | | 단계 5 | O / X | |

    2 AI 협업 설계서 작성 — Layer 2 적용

    6회차에서 배운 목적-규칙-맥락 프레임워크를 적용합니다.

    **(1) 목적 (Purpose)**: 이 시스템은 왜 존재하는가?
    이 시스템의 목적:
    이 시스템이 없으면 어떤 문제가 생기는가:
    **(2) 규칙 (Rules)**: 어떤 기준을 따라야 하는가?
    입력 규칙 (AI에게 무엇을 주는가): - 매번 제공할 정보: - 정보의 형식:
    처리 규칙 (AI가 어떻게 처리해야 하는가): - 필수 포함 항목: - 금지 사항: - 분량/형식 기준:
    출력 규칙 (결과물은 어떤 형태여야 하는가): - 출력 형식: - 품질 기준:
    **(3) 맥락 (Context)**: 판단에 필요한 배경 정보는?
    사용자 정보: (예: 고1, 문과 선택, 수학 약점 보완 중) 상황 정보: (예: 중간고사 2주 전, 주 1회 사용 예정) 톤/스타일: (예: 친근하지만 정확한 톤, 격려 포함)
    **(4) 전체를 하나의 시스템 설명으로 합치기** 위의 목적, 규칙, 맥락을 합쳐서, AI에게 전달할 수 있는 하나의 "시스템 설명"을 작성해 봅시다.
    [나의 AI 활용 시스템 — "________________ 시스템"] 당신은 ______________ 을/를 도와주는 시스템입니다. [목적] (위에서 작성한 목적을 여기에 정리) [규칙] 1. (입력 규칙) 2. (처리 규칙) 3. (출력 규칙) [맥락] (위에서 작성한 맥락을 여기에 정리) [품질 기준] (이 결과물이 "좋다"는 것은 어떤 뜻인가?)

    3 시스템 테스트 — AI와 실제 대화

    Step 2에서 작성한 시스템 설명을 실제 AI에게 전달하고, 작동하는지 테스트해 봅시다.

    **테스트 방법**: 1. AI 대화 도구를 엽니다 (ChatGPT, Claude 등 무엇이든 괜찮습니다) 2. Step 2에서 작성한 "시스템 설명"을 AI에게 전달합니다 3. 실제 데이터(이번 주 학습 내용, 최근 읽은 책 등)를 입력합니다 4. 결과를 확인합니다 | 항목 | 기록 | |------|------| | 사용한 AI 도구 | | | 전달한 시스템 설명 | (Step 2의 내용) | | 입력한 실제 데이터 | | | AI의 응답 | (핵심만 메모) | | 잘 된 점 | | | 기대와 다른 점 | |

    4 개선점 기록

    테스트 결과를 바탕으로, 시스템의 개선점을 정리합니다.

    **(1) 발견한 문제점** | 문제 | 원인 추정 | 수정 방향 | |------|----------|----------| | | | | | | | | | | | | **(2) 수정할 규칙**
    [변경 전] [변경 후] [변경 이유]
    **(3) 자기 점검 체크리스트** 나의 시스템이 "생성 장치"로서 제대로 작동하는지 점검해 봅시다: - [ ] **반복 가능한가?** — 다음에 같은 업무가 생겼을 때, 이 시스템을 그대로 사용할 수 있는가? - [ ] **일관적인가?** — 매번 비슷한 품질의 결과물이 나올 수 있는가? - [ ] **개선 가능한가?** — 문제가 발견되면 규칙만 수정해서 개선할 수 있는가? - [ ] **전달 가능한가?** — 이 시스템 설명을 다른 사람에게 주면, 그 사람도 사용할 수 있는가? - [ ] **Layer 1이 적용되었는가?** — 문제가 구조적으로 분해되어 있는가? - [ ] **Layer 2가 적용되었는가?** — 목적/규칙/맥락이 명확하게 작성되어 있는가?

    첫 테스트에서 완벽한 결과가 나오지 않는 것이 정상입니다

    중요한 것은 "어디가 부족한지 발견하는 것"입니다. AI 없이도 설계서를 친구에게 주고, 친구가 AI 역할을 해보는 것도 좋은 방법입니다. 친구가 설계서만 보고 결과물을 만들어보면, 설계서에 빠진 부분이 어디인지 더 명확하게 드러납니다.

    AI가 모든 단계를 도와야 하는 것은 아닙니다

    "이 단계는 내가 직접 해야 한다"도 중요한 판단입니다. 예를 들어, "나의 생각 정리"는 AI가 대신할 수 없습니다. 사람의 역할과 AI의 역할을 명확히 구분하는 것이 좋은 시스템의 조건입니다.

    💬 상호 피드백 활동¶

    자신의 시스템을 친구에게 공유하고 피드백을 주고받아 봅시다. 핵심 질문은 단 하나입니다:

    "이 시스템을 다른 사람이 그대로 쓸 수 있는가?"

    자신의 시스템을 다음 구조로 정리해서 공유해 봅시다:

    1. "저는 ______ 업무를 시스템으로 만들었습니다."
    2. "이 업무를 ______ 단계로 분해했고, AI가 돕는 부분은 ____입니다."
    3. "시스템의 핵심 규칙은 ______입니다."
    4. "테스트해보니 ______은 잘 됐고, ______은 개선이 필요합니다."
    5. "이 시스템의 이름은 '__________'입니다."

    피드백을 줄 때는 다음 기준을 활용해 보세요:

    피드백 항목 질문
    명확성 시스템 설명을 읽으면, AI가 무엇을 해야 하는지 바로 이해할 수 있나요?
    완전성 빠진 규칙이나 기준이 있나요? 추가하면 좋을 것은?
    반복 가능성 이 시스템을 다음 달에 다시 사용할 때, 수정 없이 그대로 쓸 수 있나요?
    전달 가능성 다른 사람이 이 시스템 설명만 보고 바로 사용할 수 있나요?

    구체적인 피드백이 좋은 피드백입니다

    "잘 했어요", "좋아요" 같은 모호한 말보다, "무엇이 좋은지, 무엇을 추가하면 더 좋은지"를 구체적으로 말하는 것이 중요합니다. 피드백을 주는 것도 연습입니다.

    📌 보충 자료: 생성 장치 설계 상세 예시¶

    아래는 "시험 오답 분석 시스템"을 생성 장치로 설계한 완전한 예시입니다. 실습에서 참고하되, 그대로 베끼지 말고 자기 업무에 맞게 변형해 주세요.

    펼쳐보기: 나의 오답 탐정 시스템 — 완전한 설계 예시

    시스템 이름: 나의 오답 탐정 시스템

    [Step 1: 문제 분해]

    순서 하위 단계 AI 역할
    1 틀린 문제 수집 X (내가 직접 입력)
    2 오답 유형 분류 O (유형 분류 기준에 따라 분류)
    3 원인 분석 O (질문으로 원인 탐색 유도)
    4 관련 개념 연결 O (교과서 단원과 연결)
    5 복습 계획 수립 O (우선순위 기준에 따라 계획 생성)

    [Step 2: AI 협업 설계서]

    [나의 오답 탐정 시스템]

당신은 고등학생의 시험 오답을 분석하고 복습 계획을 세워주는 시스템입니다.

[목적]
매 시험 후 틀린 문제를 체계적으로 분석하여, 같은 실수를 반복하지 않도록 돕는다.

[규칙]
1. 입력: 과목, 단원, 문제 내용, 내가 쓴 답, 정답을 받는다
2. 분류: 오답 유형을 다음 3가지로 분류한다
   - 개념 오류 (개념 자체를 잘못 이해)
   - 적용 실수 (개념은 알지만 적용을 잘못)
   - 부주의 (계산 실수, 문제 잘못 읽음)
3. 분석: 각 문제에 대해 "왜 틀렸는가?"를 질문 형태로 제시한다
   (바로 답을 주지 말고, 내가 생각하게 유도한다)
4. 출력: 아래 형식으로 정리한다
   | 과목 | 단원 | 유형 | 원인 요약 | 복습 우선순위 |
5. 우선순위: 개념 오류 > 적용 실수 > 부주의 순서

[맥락]
- 고등학교 1학년, 자연계열 선택
- 수학과 과학에서 오답이 많은 편
- 시험은 한 달에 1~2회
- 결과보다 원인 파악이 목표

[품질 기준]
- 분류가 정확한가?
- "왜 틀렸는가?" 질문이 사고를 유도하는가?
- 복습 우선순위가 합리적인가?

    [Step 3: 테스트 결과]

    • 잘 된 점: 오답 유형 분류가 명확함, 복습 우선순위가 도움됨
    • 개선할 점: "부주의"로 분류된 것 중 실제로는 "적용 실수"인 것이 있었음 → 분류 기준을 더 구체화 필요

    [Step 4: 개선]

    • 변경: "부주의" 분류에 하위 기준 추가 (계산 실수 / 문제 오독 / 시간 부족)
    • 추가: 이전 시험 오답과의 반복 여부를 체크하는 규칙

    📖 자주 묻는 질문¶

    시스템을 만들면 AI가 알아서 다 해주는 건가요?

    아닙니다. 생성 장치는 AI에게 기준을 주는 것이지, AI에게 모든 것을 맡기는 것이 아닙니다. 7회차에서 배운 것처럼, 사고의 주도권은 항상 여러분에게 있어야 합니다. 시스템은 "AI가 나를 도울 때의 기준"이지, "AI가 나를 대신하는 장치"가 아닙니다.

    한 번 만들면 끝인가요?

    아닙니다. 좋은 생성 장치는 계속 개선됩니다. 사용할 때마다 "어디가 부족한가?"를 기록하고, 규칙을 업데이트하면 점점 더 좋아집니다. 요리사 B의 요리 노트도 처음에는 허술했지만, 계속 메모를 추가하면서 완성되어갔겠죠.

    꼭 AI를 써야 하나요? 그냥 체크리스트를 만들어도 되지 않나요?

    매우 좋은 질문입니다. 사실 체크리스트도 일종의 생성 장치입니다. AI를 사용하면 더 복잡한 처리(분류, 요약, 연결 등)가 가능해지는 것이지, AI가 반드시 필요한 것은 아닙니다. 핵심은 "기준을 설계하는 사고방식"이며, AI는 그 기준을 더 효과적으로 실행하는 도구입니다.

    제 시스템이 너무 단순한 것 같아요.

    괜찮습니다. 처음부터 복잡한 시스템을 만들 필요가 없습니다. 단순하지만 실제로 작동하는 시스템이, 복잡하지만 사용하지 않는 시스템보다 100배 낫습니다. 단순한 시스템에서 시작해서 점점 규칙을 추가하는 것이 올바른 방향입니다.

    다른 친구의 시스템이 더 좋아 보여요.

    비교할 필요가 없습니다. 시스템은 "자기 문제"를 "자기 상황"에 맞게 설계하는 것이기 때문에, 같은 업무라도 사람마다 다른 시스템이 나오는 것이 당연합니다. 오히려 모두 같은 시스템이 나왔다면, 자기 상황을 충분히 반영하지 못한 것일 수 있습니다.

    📖 정리: Layer 2 전체 회고¶

    Layer 2가 마무리되었습니다. 5~8회차에서 배운 것을 한눈에 정리해 봅시다.

    Layer 2: AI 협업 설계력 — 전체 여정

5회차: "AI에게 시키는 방법에도 수준이 있다"
  → 수준 1(직접 요청) → 수준 2(패턴 기반) → 수준 3(시스템 설계)
  → 물고기 vs 낚시 vs 양식장

6회차: "잘 시키려면 설계서가 필요하다"
  → 목적(왜?) + 규칙(어떻게?) + 맥락(무엇을?)
  → AI 협업 설계서 작성

7회차: "만들어줘보다 생각해봐가 낫다"
  → 지시적 대화 vs 탐색적 대화
  → 사고의 주도권은 내가 유지

8회차: "하나의 결과물이 아니라 시스템을 만든다" ← 오늘
  → 생성 장치(Harness) = 반복 가능한 AI 활용 시스템
  → Layer 1(구조적 사고) + Layer 2(AI 협업 설계) = 통합
    "결과물 하나를 만드는 사람이 아니라, 결과물을 만드는 시스템을 설계하는 사람이 되자."

    자기 성찰 질문¶

    오늘 학습을 마무리하며, 스스로에게 물어봅시다:

    1. "오늘 만든 시스템을 내일 실제로 사용해볼 수 있을까?"
    2. "1회차에서 처음 문제 분해를 배웠을 때와 지금, 무엇이 달라졌을까?"
    3. "AI에게 '시키는 방법'이 바뀌면, 결과물도 바뀔 수 있다는 것을 체감했는가?"

    심화 과제 (선택)¶

    더 깊이 해보고 싶다면 아래 과제를 시도해 보세요.

    과제 1: 시스템 2주 실전 테스트

    오늘 만든 시스템을 실제로 2주간 사용해 보세요. 매번 사용 후 "잘 된 점 / 개선할 점"을 한 줄씩 기록하고, 2주 후 처음 버전과 개선된 버전을 비교해 보세요.

    과제 2: 시스템 교환 실험

    친구와 시스템을 교환하여, 상대방의 시스템을 직접 사용해 보세요. "설명만 보고 사용할 수 있었는가?" "어디가 불분명했는가?"를 기록하고, 이 피드백을 바탕으로 시스템을 개선하세요.

    과제 3: 두 번째 시스템 만들기

    다른 반복 업무를 하나 더 골라서, 두 번째 시스템을 만들어 보세요. 첫 번째 시스템을 만들 때와 비교했을 때 더 쉬워졌나요? 왜 그럴까요? (힌트: 이것이 바로 Layer 1의 "패턴 인식"입니다. 시스템을 만드는 과정 자체에도 패턴이 있습니다.)

    📚 다음 시간 예고: Layer 3로의 전환

    Layer 1에서 우리는 "어떻게 생각할 것인가"를 배웠습니다. Layer 2에서 우리는 "어떻게 시킬 것인가"를 배웠습니다.

    다음 시간부터는 Layer 3: 분야 융합 적용력이 시작됩니다. 마지막 질문을 던집니다:

    "어디에 쓸 것인가?"

    기술 자체가 중요한 것이 아닙니다. 나의 관심 분야, 나의 교과, 나의 일상에서 AI가 정말로 가치를 만들 수 있는 지점은 어디일까요?

    9회차에서는 "나의 Something 찾기"를 합니다. 여러분 각자의 관심사와 AI를 연결하는 시간입니다. 기대해 주세요.

    8회차 핵심 요약

    • 생성 장치(Harness) = 결과물이 아니라, 결과물을 반복적으로 만들어내는 구조
    • 생성 장치를 만들려면 Layer 1(문제 분해) + Layer 2(설계서 작성)가 모두 필요하다
    • 좋은 시스템의 조건: 반복 가능, 일관적, 개선 가능, 전달 가능
    • 완벽한 시스템은 없다 — 만들고, 테스트하고, 개선하는 과정이 핵심이다
